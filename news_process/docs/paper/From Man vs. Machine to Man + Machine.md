# 基于《From Man vs. Machine to Man + Machine》的项目审核与优化计划

=========================================
## 第一部分：基于参考论文的项目分析与诊断报告

### 1. 范式映射与盲区诊断
**核心机制**：Cao et al. (2024) 突破了单纯的“机器替代人类（Man vs. Machine）”框架，提出了**“人机协同（Man + Machine）”的混合预测范式**，并创造性地使用了**“机器去偏人类（Machine-debiased Man, MDM）”**方法。研究发现，当商业环境存在高度不对称性（如公司具有高无形资产占比、低流动性、高违约风险或处于快变竞争环境）时，人类在捕捉制度性信息和处理非透明任务上能够击败机器；而在处理透明且海量的信息时，机器占据绝对优势。最终结论表明，“人马混合（Centaur / Man + Machine）”不仅能大幅降低极端预测错误，还能达到最优性能。

**当前项目盲区**：目前 `news_process` 项目在 `32_news_llms_human.py` 和 `33_news_llms_evaluation.py` 阶段，主要是将人类的判定作为“黄金标准（Gold Standard）”来计算 LLM 的分类精确度、召回率、F1和诊断系统关联性误差。这依然停留在传统的“机器对标验证”阶段。在深层次的金融实证中，不应仅仅停留于纠结某个 LLM 是否逼近了人工，或者简单的对错判断，而是未能充分利用不同信息环境下“机器与人类（或先验市场专业信息）的相对比较优势”。如果将 LLM 情感分析视为基础机器输入，现有管道缺少一种能够在高信息不对称和复杂极端状态下引入“降噪与人工先验补充”（即协同）的思想。

### 2. 实质性改进项（宁缺毋滥）

**改进 A：基于企业信息不对称环境特征的“动态人机/模型权重分配（Context-Aware Man+Machine Hybrid）”**
- **具体修改建议**：在 `41_panel_encode_aggregate.py` （序列情感聚合）或 `44_panel_iv_did.py` 阶段，不要单调地使用均等加权的 LLM 情感得分进行直接回归。而是根据表征企业“信息不对称程度（Information Asymmetry）”的变量（如：Amihud流动性、市值、无形资产占比 Intangible Assets、违约距离 Distance to Default），构建交互项（Interaction terms）或采用机器学习集成模型计算动态置信度。由于底层代码在模块 33 发现错分率，这一步应根据信息透明度降阶，对 LLM 给出的得分引入条件衰减。
- **论文依据**：Cao et al. 发现人类分析师应对高无形资产和低流动资金公司的预测胜率更高（Table 4）。这表明 AI 在分析这些公司时会有系统性的能力天花板与极限。
- **预期边际贡献**：彻底打破“一刀切”的情感构造模式，解释为什么 AI 情感因子在某些公司中具有高度解释力，而在另一些公司中存在噪音（解释异质性机制）。这能够极大地提升实证结果的前沿理论厚度。

**改进 B：引入类似于 MDM 的“机器纠偏机制（LLM-Debiasing Filter）”**
- **具体修改建议**：在后续的主特征回归之前，提取能够代表过去预测偏差的数据（即在不同行业、不同分析师背景下的典型错误偏好），利用预测出的纠偏误差量值从基础的 LLM 情感序列（或特定情感词典输出）中减去，构造一个更加纯净的“去偏版情感因子 (Debiased Sentiment)”。
- **论文依据**：论文在 3.3 节提出 MDM（Machine-Debiased Man）的概念，证明通过机器学习矫正已知偏误后，人类落后于机器的预测差距填补了22.2%。同理，大语言模型也会自带某些系统性偏往正面/温和结论的偏误。
- **预期边际贡献**：针对审稿人可能提出的“大模型本身自带过度平滑或正向讨好倾向（Positivity Bias/AI aligning bias）”提供数学层面的反驳防线，增强情感变量设计的纯洁度。

### 3. 冗余剥离
**剥离目标**：在当前版本中，项目并存使用了 `22_tone_words.py` (词库法) 和 `23_tone_berts.py` (中小参数监督模型)。
- **操作建议**：既然我们主要采用前沿 LLM（如框架中引入的多任务联调 `21_tone_llms.py`），且论文证明深度混合的大模型可以胜任大规模无结构降维，继续为词典法和古早的弱化 BERT 重复构造并行的实证链条属于分散精力的“伪需求”。
- **剔除决定**：建议在下游的基准实证验证阶段，将词典法得分仅仅降级为基准回归中的比较列（只在稳健性检验 Robustness Checks 中露面一两列），把主要的精力、存储和计算开销收敛于 LLM 的聚合与修正，避免无效工作量。

## 第二部分：项目重构与优化执行计划书

### 1. 优先级排布
- **速赢项（Quick Wins）**：
  为数据面板提取无形资产占比（Intangible Asset Ratio）、Amihud 日度流动性估计和对数市值（Log Market Cap）。并在未来的回归中直接加入 `LLM_Sentiment × Intangibility`、`LLM_Sentiment × Illiquidity`，以极低的改造成本验证因果机制。
- **核心攻坚项**：
  构建一个模拟“Man + Machine”的人马座混合因子（Centaur Hybrid Factor），利用已有人类专家标注/核实的数据子集作参考基准，采用集成算法合并生成基于特征环境自适应调节的主解释变量。

### 2. 阶段化执行指令 (SOP)

**阶段一（机制重塑/数据清洗）**
- 操作区域：`00_preprocessing.py` 或新建面板数据融合脚本 `0x_financial_context.py`
- 执行指令：拉取并计算企业面板的四个异质性特征：(1) 对数总市值（代表信息透明规模），(2) Amihud 流动性指标（代表交易信息摩擦），(3) 资产无形化率（Intangible Assets / Total Assets，代表企业信息不可观测性），(4) 距违约距离（如果可用）。
- 交付物标准：输出包含以上变量时间序列的标准化面板 Parquet 数据。

**阶段二（实证/模型重构与检验）**
- 操作区域：`41_panel_encode_aggregate.py`
- 执行指令：基于阶段一获取的外生信息环境指标，设立惩罚机制或非线性加权网络。在生成核心面板舆情指标时，对“软信息/高无形资产公司”的新闻 LLM 情感得分缩水一个置信度乘数（或保留专家偏误修正值，即MDM流程），作为新的去偏因子列（如 `sent_hybrid_debiased`）。
- 交付物标准：新增融合后的“混合加权情感分数据列”，用于面板回归输入层。

**阶段三（结论重构）**
- 操作区域：`44_panel_iv_did.py` 与 `45_panel_export_main.py`
- 执行指令：在呈现 LaTeX 结果总表时，单独设立一个 "Context-dependent Subsamples"（基于环境依赖的子样本）Panel。按照高/低无形资产、高/低流动性将样本一分为二，对比“原始 LLM 打分”和“结合异质环境的去偏混合打分”两套系统的 R-squared 与经济显著程度，明确验证协同混合框架在消除极端偏差里的卓越效用。

### 3. 风险预案 (Plan B)
- **卡点 1**：如果 Amihud 流动性高频数据或精准的研发、资本无形化比率在爬虫或财务库中存在系统性缺失。
  - **Plan B**：退一步使用企业上市年限（Age）或更简单的公司总资产级别（四分位数）直接代替。对于无形资产，可以用企业所属国标行业（例如将其分为制造业 vs. TMT及服务业）设立虚拟变量（Dummy Variable）进行粗颗粒度替代。
- **卡点 2**：如果训练类似于 MDM 的特征纠偏多维机器学习模型在实施上过度占用开发时间。
  - **Plan B**：放弃模型化的预测除偏，改用文献提供的启发式规则除偏：基于以往分析师或市场已知结论——直接设定条件（例如：在科技行业的大量好消息爆发时强行衰减一定的分值作为 Penalty 惩罚项），来验证剔除系统性偏差化对预测力的提升。
