# 基于《网络安全风险治理与企业创新——基于大语言模型的识别与发现》的项目诊断与执行计划

## 第一部分：基于参考论文的项目分析与诊断报告

### 1. 范式映射与盲区诊断
**论文核心机制**：该论文利用大语言模型（ERNIE）精准识别企业年报中“实质性”的网络安全风险治理行为，证实其通过提升数据利用效率、稳固合作创新关系及缓解融资约束来促进企业创新，并创新性地发现其在供应链纵向关系（上下游企业）中存在非对称的创新溢出效应。
**当前项目落差**：当前 `news_process` 项目在对新闻进行金融科技（FinTech）分类与情感验证的工作中使用了 LLM，整个识别验证逻辑（Unified CoT）优于论文采用的二分类范式。然而，对标论文，本项目在**主题维度界定**和**传导效应评估**上存在两个盲区：
(1) **内涵缺失**：当前流水线 `config.yaml` 中的金融科技主题（AI、区块链、大数据风控等）偏向“进攻型”数字业务扩张，忽略了被该论文证实极为关键的“防守型/底座型”技术——网络与数据安全风险治理。
(2) **视角局限**：当前研究设计止步于 Bank-Year（银行主体层面）的内部影响，缺失了对其“下游”实体经济（即借款企业）创新的外部溢出效应探讨。

### 2. 实质性改进项（宁缺毋滥）
- **改进 A：将“网络安全与数据治理”纳入金融科技度量体系，构建“攻防双维”解析**
  - **具体修改建议**：在 `config.yaml` 阶段 21 的 Prompt 的 `fintech_topic` 列表中及 `fintech_dict.json` 词典中，显式加入“网络安全防御、数据隐私保护、容灾备份”。在后续面板产出（阶段 45）中将指标解构为“进攻性金融科技业务”和“防守性网络数据安全”。
  - **论文依据**：论文实证证明了网络安全治理是保障核心数据安全、提升数据利用效率转化为创新的底层前置条件。
  - **边际贡献**：弥补原设计中对商业银行金融科技“合规与防范”风险属性的刻画缺失，可研究银行数字底座安全建设如何内生性地化解信用风险，解决单一测度金融科技进攻型业务带来的偏误。

- **改进 B：构建从商业银行向下游实体企业的“创新信贷溢出效应”（Bank-to-Firm Spillover）**
  - **具体修改建议**：将构建完毕的 Bank-Year 金融科技新闻与情感面板，与上市企业（Firm-Year）贷款授信明细库匹配，考察银行在网络安全与金融科技新闻上的情感（事件）能否外溢并促进依赖该行的借款企业创新产出大幅提升。
  - **论文依据**：论文第五部分（表 6、表 7）构建了“中心企业—下游客户/上游供应商”的分析框架，证实了网络安全治理沿着业务链存在显著溢出效应。
  - **边际贡献**：银行的“客户”主要是借贷关联企业。将流水线从单一主体的绩效分析向下游实体溢出效应延伸，能强有力地回应金融领域关于“金融科技赋能实体经济/脱实向虚”的核心学术关切。

### 3. 冗余剥离（维持原状指令）
- **测度范式维持原状：坚决保留本项目现有的 LLM + Unified CoT 设计**。本项目整合了主体消歧、实质性关联和基于语境的情感判定，且内嵌了 Entity Masking 等稳健性框架，明显优于本论文单纯提取语句作简单二分类的早期 NLP 设计。严禁因形式主义进行降级。
- **内生性检验维持原状：拒绝仿效本论文的距离工具变量**。本论文采用横截面的“企业距信息安全专业高校距离”作 IV，极容易被高阶固定效应吸收。本项目 40+ 阶段已配置 `Bartik Shift-Share IV (29套)` 及 `DID 政策冲击变量`，技术等级远超同类研究，此处须严格维持现有外生冲击设计方案。

## 第二部分：项目重构与优化执行计划书

### 1. 优先级排布
- **速赢项（Quick Wins）**：修订字典与特征提取机制，极低成本引入网络安全属性的捕捉。
- **核心攻坚项**：跨库匹配银行与实体企业的联系网络，完成从 Bank Level 向 Firm Level 溢出的面板数据融合。

### 2. 阶段化执行指令 (SOP)

**阶段一（机制重塑与底层识别扩展）：**
1. **修改字典**：调整 `config/fintech_dict.json`，补充“隐私计算”“零信任架构”“反欺诈风控模型”“数据防泄漏”等安全类底层技术词汇。
2. **微调提示词**：修改 `config.yaml` 阶段 21，将 Prompt 中的举例扩展为 `（AI、区块链、数字货币、大数据风控、隐私计算与网络安全、云计算等）`。
3. **交付物标准**：使得清洗完成的 `21_tone_llms.parquet` 能精细捕捉到银行在系统安全与数据治理方向的投入事件。

**阶段二（实证面板与溢出效应重构）：**
1. **维度拆解**：拓展 `45_panel_export_main.py` 代码，基于正则对保留的新闻做二元解构，分别生成 `FinTech_Expansion` (拓展型指标) 与 `FinTech_Security` (安全治理指标)。
2. **银企关联网络建立 (核心指令)**：获取 CSMAR/CNRDS 银行贷款明细数据，构建企业与其主导贷款行间的映射关系。构建下游溢出回归模型：
   $$Firm\_Innovation_{j,t} = \alpha + \beta_1 Bank\_Fintech\_Security_{i,t-1} + \dots$$
3. **高维控制指令**：在溢出模型实证代码中，强制挂载 `Firm FE` 以及 `City×Year FE`，同时开启 Firm 或 Bank 维度的聚类稳健标准误计算。

**阶段三（检验与结论锚定）：**
1. **结论导向验证**：需重点检验“银行业的网络安全风险治理”（而非单纯发贷活动），是否通过提升核心系统防范能力，降低了系统性坏账并向借款实体输出更稳定的信用流动性，从而促进其实体创新。

### 3. 风险预案 (Plan B)
- **执行致命卡点预判**：银企一一映射的精确微观贷款数据（Syndicated Loans 或具体银行借款去向）由于央行脱敏要求，存在覆盖率极低的断层风险，可能导致下游溢出的样本量不足以支撑回归收敛。
- **替代方案 (Plan B)**：放弃企业级别的微观匹配，转而在宏观地市级实施 **空间溢出加权方案**。通过收集并计算各银行在全国各城市的分支机构网点数量占比（Branch Weights），以分支占比计算各市银行金融科技（含安全治理）加权普及度构建城市面板。回归模型调整为分析某地的整体银行业金融科技安全底板加固，是否降低了该区域内中小企业的融资约束及促进全域创新产出。
