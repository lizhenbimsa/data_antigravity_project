# CEO turnover, sequential disclosure, and stock returns 论文评估与项目重构执行计划

=========================================
## 第一部分：基于参考论文的项目分析与诊断报告

### 1. 范式映射与盲区诊断
**核心机制提炼**：参考论文指出，管理层在进行信息披露时具有强烈的“预期管理（Expectation Management）”动机，并且会采取顺序化披露策略——先释放即期或历史的负面消息（降低基准预期/洗大澡），随后释放关于长期的正面消息（释放能力信号）。
**当前项目盲区**：目前流水线中的情感萃取模块（如 `21_tone_llms.py` 以及基于词典和BERT的模块）仅仅提取了单一维度的静态 `sentiment`（正面/中性/负面）。这种“情感同质化”聚合会引起严重的测量偏差（Aggregation Bias）。例如，一篇声称“受历史包袱拖累当期利润受损，但远期金融科技转型前景广阔”的新闻，会被粗暴地拉平为“中性”，完全抹杀了其中包含的战略性预期管理信息，导致由于“洗大澡”等内生动机造成的估计偏误无法被控制。

### 2. 实质性改进项（宁缺毋滥）
- **改进 A：引入多期限情感分解（Multi-horizon Sentiment Decomposition）**
  - **[写明具体修改建议]**：全面重构 `21_tone_llms.py` 的 Prompt 体系，废弃单一的 `sentiment` 输出。要求 LLM 必须分别提取 `short_term_sentiment`（短期/即期业绩情感）与 `long_term_sentiment`（中长期战略与前景情感），并构造 `optimism_spread` (长期-短期乐观差值)。
  - **[标明论文依据]**：论文第3.5节 “LLM-based evidence”，明确使用 ChatGPT 提取 Managerial optimism 的不同期限维度（short-term optimism vs long-term optimism）。
  - **[阐述预期的边际贡献/解决的内生性问题]**：解决整体情感测量的混淆偏误。能够精准捕捉银行通过“金融科技转型”作为信号传递手段的预期管理行为，过滤掉因历史包袱导致的短期负面噪声。

- **改进 B：战略披露意图与归因分析（Strategic Disclosure Likelihood）**
  - **[写明具体修改建议]**：在 LLM 的提取结构中加入 `strategic_intent` 概率判断指标，测量新闻文本中是否含有将负面业绩归咎于前任/外部环境、或刻意压低预期的语言特征。
  - **[标明论文依据]**：论文第3.5节，使用 LLM 提取 "strategic disclosure likelihood" (i.e., attributing poor performance to the previous management)。
  - **[阐述预期的边际贡献/解决的内生性问题]**：直接控制管理层的策略性披露动机这一遗漏变量（Omitted Variables）。使得金融科技发展对银行绩效的因果推断更加稳健，排除“为了洗大澡而披露”所带来的内生选择偏误。

### 3. 冗余剥离
明确指出当前项目（如 `22_tone_words.py` 和 `23_tone_berts.py`）中基于传统词典和早期BERT模型的静态情感计算模块偏离了前沿学术主线，对本项目核心价值贡献极低。
词典法（即便加了 TF-IDF 与否定转折规则）与基础 BERT 根本无法理解“短期利空与长期利好”并存的复杂修辞和管理层预期管理策略。建议直接作为纯 baseline 辅助，或从主线核心实证模型中剔除，核心实证变量应全面转向大模型驱动的多期限、多意图提取。

## 第二部分：项目重构与优化执行计划书

### 1. 优先级排布
- **速赢项（Quick Wins）**：修改 `config/config.yaml` 中的 LLM Prompt 模板及其 JSON 输出格式，新增短期情感、长期情感与战略披露意图标注。此项代码修改成本极低，预期学术收益巨大。
- **核心攻坚项**：重构 `41_panel_encode_aggregate.py` 与 `45_panel_export_main.py`，将细粒度的多期限情感和意图得分聚合成 Panel 面板数据中的核心解释变量、控制变量与异质性指标。

### 2. 阶段化执行指令 (SOP)

**阶段一（机制重塑/数据清洗）：**
- **动作 1**：修改 `config/config.yaml` 中的 `prompt_template` 及 `<output_format>`。
  - 移除原有的单一 `sentiment` 和 `sentiment_reason` 字段。
  - 增加字段：`short_term_sentiment` (短期情感：正面/中性/负面)、`long_term_sentiment` (中长期情感：正面/中性/负面)、`strategic_disclosure_likelihood` (0.0~1.0 浮点数，测量预期管理和策略归因程度)。
- **动作 2**：更新 `21_tone_llms.py` 以适配新增的多期限情感与披露分类字段，清理历史缓存后重新运行以生成包含多期情感的 `21_tone_llms.parquet` 数据。
- **交付物标准**：能够输出包含短/长期情感与策略披露概率字段的高质量 Parquet 数据集，且 JSON 解析错误率控制在万分之五以内。

**阶段二（实证/模型重构与检验）：**
- **动作 1**：在 `41_panel_encode_aggregate.py` 中新增指标构建逻辑。分别计算银行年度维度的平均短期积极度、长期积极度，并构建差值核心指标 `optimism_spread = long_term_tone - short_term_tone`，以及年度层面的平均被感知策略性披露意图得分（`strategic_intent_index`）。
- **动作 2**：在 `45_panel_export_main.py` 的数据融合阶段，纳入这些新增特征作为回归的控制变量或分组变量进行输出。
- **稳健性检验标准**：测试传统的字典法情感是否只能反映即期收益而无法预示长期价值（即复刻论文机制作为稳健性对照试验）。

**阶段三（结论重构）：**
- **动作 1**：全面更新基于回归分析的模型配置或代码设计（如 `51_falsification_test.py` 等），将策略披露倾向作为重要控制项，并尝试论证金融科技发布是管理层引导长期预期的工具。

### 3. 风险预案 (Plan B)
- **风险卡点**：要求大语言模型单一请求内同时进行“主体识别真伪判定”、“多期限情感分解”和“战略意图量化评分”，指令复杂度急剧过高。可能导致现有的低成本/快速模型（如 gpt-5.4-nano, claude-haiku）注意力涣散，输出严重幻觉或 JSON 格式崩塌（解析失败）。
- **替代预案 (Plan B)**：采用**多阶段 Agent 级联提取模式**。将 LLM 调用硬拆为两步流水线：
  1. Pipeline 第一步仅负责“语义是否聚焦目标银行与金融科技主题”真伪验证。 
  2. Pipeline 第二步仅针对前一步中被判定为 True 的事实新闻，传入更强参数级别的模型（如 Claude 3.5 Sonnet / GPT-4o 等），专项用于精准的复杂因果归因、期限拆解与策略意图测量。以此牺牲处理时间来确保顶刊要求的提取有效率（Validity）。
