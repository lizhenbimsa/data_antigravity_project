# 执行计划书：Corporate responses to generative AI_ Early evidence from conference calls

## 第一部分：基于参考论文的项目分析与诊断报告

### 1. 范式映射与盲区诊断
**论文核心范式**：论文《Corporate responses to generative AI: early evidence from conference calls》在衡量企业对生成式AI冲击的反应时，不止步于“提及频率（Intensity）”和“情感倾向（Sentiment）”，更创造性地利用大语言模型（ChatGPT-4）提取了“**实质性行动举措（Action Initiatives）**”这一高阶维度，并论证了只有叠加了行动举措的正面讨论才能带来最确定的市场正向反应。此外，论文指出创新输出产出（如专利而非单纯的研发投入）、网络安全威胁以及客户/劳动力暴露度是异质性反应的关键宏观驱动因素。
**当前项目盲区**：审查项目 `config/config.yaml` 中第21阶段的 Unified CoT Prompt 发现，当前流水线仅实现了“金融科技主题校验”和“情感倾向分析（正/中/负）”，**严重缺失“实质行动举措（Action Initiatives）”的鉴别能力**。这极易将金融科技领域的“高管空泛表态/媒体跟风炒作”（AI Washing / Fintech Washing）与“实质性技术部署”混为一谈，导致由于未过滤口水新闻，面板数据中的最终统计强度指标可能包含巨大的漂绿噪音。此外，项目采用的模型配置存在堆砌冗余的问题。

### 2. 实质性改进项（宁缺毋滥）
- **改进 A：在统一 LLM 语义精筛（21阶段）中新增“行动举措（Action Initiative）”识别维度**
  - **[论文依据]**：论文 Section 3.2.3 (Initiative-related versus other GAI discussions) 中通过大语言模型直接分离了“包含行动倡议的发言”与“泛泛而谈的发言”，揭示纯泛泛而谈缺乏经济约束力和真实市场影响。
  - **[预期边际贡献/解决的内生性问题]**：通过在 Prompt_template 和 JSON output 中新增 `has_action_initiative` 布尔状态字段，项目能够将新闻流分解为“空泛讨论（Non-Initiative）”与“实质动作（Initiative）”。这在后续的实证检验中将彻底根除“漂绿行为（Washing bias）”带来的内生测量误差，极大提升解释变量度量的学术纯净度与严谨度。

- **改进 B：在面板构建与因果推断框架中引入具体的产业暴露度与创新特征进行机制校验**
  - **[论文依据]**：论文 Section 5 提出，研发支出（R&D）与实质性数字推进关联性弱，真正显著的是真实的代表落地与保护的专利产出（Patents）、网络安全威胁（Cybersecurity Threats），以及劳动力维度的暴露度（Labor exposure to AI）。
  - **[预期边际贡献/解决的内生性问题]**：在组装和执行 Bank-Year 层面的异质性检验时，超越传统的银行财务指标（资本充足率、不良率等），专门采用科技维度的基底差异（诸如数字化技术专利存量、受网络安全监管的级别风险词频），能直接映射出“不同禀赋企业的内生差异”，提升因果推演的故事厚度。

### 3. 冗余剥离
- **伪需求模块：剥离冗余沉重的多模型 BERT 情感分析池（23_tone_berts 模型列表）**
- **诊断理由与论文依据**：论文证明，即便在使用简单的 Loughran-McDonald 词典建立基准情绪法（词典法）基础上，引入强劲的统一 LLM（如 ChatGPT-4）来提取高阶且困难的语义特征（行动举措），就已经能够获得顶刊级别的绝佳实证结果。
- **剥离建议**：由于这套框架在阶段21中已经前置引入了极其强大的 LLM 集群并使用了思维链（GPT-5, Gemini 3, Claude 4.5），阶段 23 堆叠的如 `hw2942`, `erlangshen` 等5个偏小的传统静态 BERT 模型能提供的边际信息增益极其有限，甚至会引入更多因为长文本截断导致的判定杂音。建议在 `config.yaml` 中剔除或停用 `tone_berts` 模块分支，秉承“最精确的现代规则词典提取基底（对应 22阶段_IDF加权） + 最强泛化大模型认知（对应 21阶段_CoT）”的双轨极简范式，避免为了方法繁琐而繁冗的形式主义，节省计算资源。

## 第二部分：项目重构与优化执行计划书

### 1. 优先级排布
- **速赢项（Quick Wins）**：
  1. 重写与升级 `config/config.yaml` 的 Unified CoT prompt，低成本实现 `has_action_initiative` 和行为类别字段的无缝联合抽提。
  2. 修改 `enabled_methods` 配置名单，优雅剔除 `tone_berts` 配置段中的高开销冗余执行逻辑。
- **核心攻坚项**：
  1. 需要对主脚本产生的全量结果数据，按照切片（整体声量与“纯实质发展声量”）单独构建并衍生两套不同阈值控制下的因子面版。

### 2. 阶段化执行指令 (SOP)

**阶段一（机制重塑/数据清洗）：**
- **核心动作指令**：
  - 更新 `config/config.yaml` 中 `prompt_template`。在原本的第一（真伪精筛）、第二（情感）阶段后，追加**第三阶段：实质性举措判定**。注入判别逻辑：“判定新闻是否披露了银行在金融科技领域的具体执行或确切部署（如产品实际上线、合作协议正式签署、重点研发专利发布）。如仅为前景吹捧、概念普及、研报预测或宏观政策引用，判为 false。”
  - 将 JSON `output_format` 拓展：
    ```json
    {
      "is_bank_fintech_news": true,
      ...
      "sentiment": "正面",
      "has_action_initiative": true/false,
      "initiative_type": "技术研发/战略合作/产品发布/内部架构/null"
    }
    ```
- **明确交付物标准**：最终配置生成的 LLM 微批处理将完全按照新 JSON Schema 输出，单次调用的颗粒度扩展但不额外增加多余调用链路。

**阶段二（实证/模型重构与检验）：**
- **核心动作指令**：
  - 在 `config.yaml` 的 `sentiment_analysis.enabled_methods` 列表中移除 `tone_berts`。
  - 面板变量生成模块（45_panel_export）重构时，需要加入条件变量聚合，产生 `bank_fintech_sentiment_all` 以及 `bank_fintech_sentiment_initiative_only`。
- **稳健性检验标准**：两者面板指标需要在统计上展现出区分度（例如：小规模商业银行在总体声量上极大，但在 initiative_only 声量上极小，凸显小行偏重“炒作洗绿”而非实干的假说检验分布现象）。

**阶段三（结论重构）：**
- **核心动作指令**：利用提取的新维度，将传统的一维线性回归转变为两步检验。先证明“金融科技整体新闻提及”对业绩表现的拉动充满噪音且回归系数偏弱；再证明剥离空口水声量后的“具备实质性倡议(Initiative)的金融科技新闻脉冲”方能展现强劲的市场定价效应和长期信贷损失抵御能力预期。

### 3. 风险预案 (Plan B)
- **致命卡点**：LLM 在执行 `has_action_initiative` 提取时发生高频的过度保守主义（False Negative 显著，即系统认为“银行签订银企战略合作协议”仍不算实质代码产品上线，大面积判为无实际动作 false）。
- **替代方案**：使用 Few-Shot 软微调策略。在 prompt 提示库中内置两例边界 Case——明确指出“具有法律约束力的备忘录签署”、“董事会批准专项科技预算”均认定为 `initiative=true`，通过提供显式判例防止模型自行拔高判别阈值至苛刻境地，并抽调200条测试样本强制先跑人工校验闭环。
