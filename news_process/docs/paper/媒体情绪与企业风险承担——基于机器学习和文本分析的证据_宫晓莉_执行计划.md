# 诊断报告与优化执行计划书：映射《媒体情绪与企业风险承担——基于机器学习和文本分析的证据》（宫晓莉，2023）

## 第一部分：基于参考论文的项目分析与诊断报告

### 1. 范式映射与盲区诊断
**核心逻辑映射**：
参考论文《媒体情绪与企业风险承担》（宫晓莉等，2023）构建了“媒体文本情绪 $\rightarrow$ 机制渠道（信息不对称、投资者情绪、分析师羊群行为） $\rightarrow$ 企业风险承担（盈利波动率、股票收益波动率）”的全景分析框架。
当前 `news_process` 项目为高度成熟度的新闻情感处理流水线（包含词典法、BERT、LLMs等），已具备高质量的自变量（文本情绪）生成能力。然而，在向最终“经济后果与面板实证”对接的 `41-45` 模块中，缺乏论文中的风险承担被解释变量设定及机制渠道映射，且未利用论文设计的同业媒体情绪构建工具变量（IV）。

**盲区诊断**：
1. **因变量与机制变量缺位**：当前流水线聚焦特征工程输出（Tone, Attention, Bartik IV），缺乏标准化的“风险承担”表征量体系；且尚未整合测度“信息不对称”、“投资者情绪”及“分析师羊群行为”三条核心传导机制的代码逻辑。
2. **底层分类器方法的代差错配**：论文重点对比了 Naive Bayes (拉普拉斯平滑)、SVM 等传统机器学习与单纯词典法；本项目使用了更为前沿的 LLMs 和金融垂直预训练 BERTs，构成了对参考论文的“降维打击”（Methodological Supremacy），但在鲁棒性检验中，可补充传统 ML 算法（如朴素贝叶斯）作为 Baseline 以迎合部分审稿人的经典偏好。
3. **工具变量（IV）构建的单一性**：本项目在 `config.yaml` 阶段 41-45 已开启 Bartik IV 与政策冲击 DID 维度，但缺失了论文中强有力的同侪溢出 IV 构建方式（以同行业/同省份其他个体的媒体情绪中位数作为 IV）。

### 2. 实质性改进项（宁缺毋滥）
*   **改进 A：增设以同业媒体情绪中位数/均值为基础的传统二维工具变量（IV）构建设施**
    *   **论文依据**：论文在稳健性检验部分使用“同行业（剔除自身）媒体情绪的中位数”作为工具变量进 2SLS 估计（参考原引文：以同行业其他个体情绪作为工具变量）。
    *   **预期贡献/解决的内生性问题**：有效缓解“由于个股/特定银行自身风险水平反向吸引媒体带有特定情绪的跟踪报道（反向因果律）”及遗漏变量所引致的内生性问题。该 IV 会与本项目已设置的 Bartik Shift-Share IV 互补，构成体系完备的双重 IV 阵列。
*   **改进 B：在主面板导出模块建立“三维机制渠道”（机制检验）交互验证项接口**
    *   **论文依据**：论文表3及后续章节严谨验证了“信息不对称”、“投资者情绪（TobinQ残差）”、“分析师行业羊群行为”三大逻辑链节点。
    *   **预期贡献/解决的内生性问题**：在 `45_panel_export_main.py` 环节设置标准化合并接口，直接衔接这些外部微观数据的合规对焦（Merge_Key），能使最终的数据输出在 Stata 中实现“一键直接跑机制”，大幅降低实证科学家的预处理成本。

### 3. 冗余剥离
*   **剔除过度繁琐的超短视窗情绪计算**：论文虽指出舆情冲击具备短期性，但针对企业综合风险承担这种慢变量（如年度波幅），采用日级滞后/五日滚动的多频度特征提取会导致数据极度稀疏。在导向 Bank-Year 面板时，应主动关闭噪音过大的微观维度模块，将算力向年度/跨季度均值聚焦。

## 第二部分：项目重构与优化执行计划书 (SOP)

### 一、 优先级排布
*   **速赢项 (Quick Wins - 高收益低成本)**：在 `45_panel_export_main.py` 中直接植入基于地区或分类的“同侪媒体情绪留一法工具变量 (LOO Peer Sentiment IV)”构建计算流。
*   **核心攻坚项 (High Effort/High Reward)**：增设机器学习的基准对照模块，通过调用 Sklearn 实现带有拉普拉斯平滑的朴素贝叶斯分类器来评测词典/BERT。由于工程改造大，置于验证环境单独测算最为稳妥。

### 二、 阶段化执行指令 (SOP)

#### 阶段一：衍生变量组与 IV 架构增强 (Data Construction)
*   **核心动作指令**：
    1. 修改 `45_panel_export_main.py`，在整合计算 Bank-Year 面板的过程增加 `Leave-One-Out (LOO) Peer Sentiment Generator` 函数。
    2. 数学逻辑：对于银行 $i$ 在第 $t$ 年的同业媒体情绪 $PeerTone_{i,t}$，取 $t$ 年内排除了该银行 $i$ 后，全样本所有新闻/所有其他银行对应情绪序列的均值及其年度中位数。
    3. 同步修改 `config.yaml` 暴露出对应参数：`compute_loo_peer_iv: true`。
*   **交付物标准**：脚本运行后生成的面板数据集 (`.parquet` 或 `.dta`) 自然携带 `iv_tone_peer_mean` 与 `iv_tone_peer_median` 这两列独立的工具变量。

#### 阶段二：基准分类模型的基线对照扩充 (Methodological Robustness)
*   **核心动作指令**：
    1. 编辑并补充 `33_news_llms_evaluation.py` 或设立对应的独立模块，以“朴素贝叶斯”和“SVM”为 Baseline，对标我们的 LLM 标注。
    2. 使用 `TfidfVectorizer` 把 `32_human_samples` 中的人工抽样（文本）做 TF-IDF 化，再投入 `MultinomialNB` 模型中计算测试集上的准确率和 F1-macro。
*   **交付物标准**：最终验证输出结果能以图表或日记形式宣告：“基于我们大模型或 BERT 所生成的泛化情感标注，在精准度指标上远超宫晓莉(2023)所使用的朴素贝叶斯基线”。这种压倒性优势是审稿答复中的“杀手锏”。

#### 阶段三：机制交互桩注入与边界管控 (Integration)
*   **核心动作指令**：
    1. 不越界将第三方分析师报表或交易流动性计算混入新闻语言特征池中进行爬取；
    2. 取而代之地，在导出的 DataFrame 末尾提供统一、高度纯净的主键对 (`BankCode`, `Year`)。
    3. 对于“信息不对称”、“分析师羊群行为”、“非执行董事薪酬”等论文异质性指标，在代码主模块中提供 `.do` 文件代码样例或数据合并注释 `merge templates`，建立外部数据的接口规约。
*   **风险预案 (Plan B)**：
    *   *卡点预判*：直接在 Python 主进程联跑金融市场数据处理会导致依赖树剧增（如需要各种 pandas_datareader、Tushare 等外部环境），破坏了流水线的部署稳健性。
    *   *替代方案*：坚决执行“流水线解耦”。所有文本挖掘侧输出结果严格收敛至“媒体情感指数”本元，确保下游研究可自行利用任何统计软件无门槛对接。

> [!IMPORTANT]
> **红线警示（Absolute Redline）**：
> 针对当前系统（LLM及金融垂直模型），切勿因论文采用了词典与初级别 ML 就倒退回旧路线，新增的基线模型必须作为“被降维打击（用作突显我们优越性的垫脚石）”的靶子出现，核心预测管道逻辑不得修改！
