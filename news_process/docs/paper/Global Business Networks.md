# Global Business Networks

【第一部分：基于参考论文的项目分析与诊断报告】

1. 范式映射与盲区诊断： 
参考论文（Breitung & Müller, 2026）的核心机制是利用最前沿的嵌入模型（Embedding models，如OpenAI和T5）处理企业描述文本以构建全球同业网络，并提出了一个重大发现即在使用基于大语言模型的嵌入技术时会由于模型底座包含了未来的训练数据而产生“前瞻性偏差（Look-ahead Bias）”。为对抗这一内生性偏差，论文证明了在向量化和语义识别前，必须使用命名实体识别（NER）技术对文本中的“特定主体标识（企业名称与产品等）”进行信息掩码隐匿（Entity Masking）。
精准落差诊断：当前 `news_process` 项目（通过其 `config.yaml` 诊断）在情感极性与真伪鉴定中大量使用了具备世界知识的先进 LLM（如 GPT-5、Gemini 3、Claude 4.5），但现有的“Entity Masking 稳健性测试（阶段36）”仅仅被配置为一个事后的抽样检验模块（判定LLM标注一致性）。在实际的主力大模型标注阶段（阶段21），系统仍然直接向模型暴露了极具标识性的【目标分析银行】。这种做法使得 LLM 在分类时极大可能调动了其预训练参数中关于该银行“未来是否成功转型或暴雷”的后验知识，从而在评判过去（如2012年）的新闻时产生严重的 Look-ahead Bias，直接导致基准测试结果偏离真实的“因果影响时间轴”。

2. 实质性改进项（宁缺毋滥）： 
- 改进 A：将“实体掩码”由后验测试升格为主干预处理层 
  -> 论文依据：Section 2.4 （Mitigating a potential look-ahead bias of LLMs）指出，直接使用包含未来信息的模型会导致时间错配的强关联，利用可靠的Transformer NER技术抹除机构名称能极大改善该偏差。 
  -> 预期的边际贡献/解决的内生性问题：彻底封堵因 LLM 预加载了目标银行“事后发展事实”而产生的识别噪音，确保提取出的金融科技关注度和情感仅基于当下的文档语义事实，消减因历史时间线崩塌带来的结果自相关与估计偏误。
- 改进 B：引入基于上下文化 Embedding 的动态同业网络以控制行业溢出效应 
  -> 论文依据：Section 2.5 确立了利用 T5-XXL / OpenAI Embedding 模型构筑高维相似度动态网络。 
  -> 预期的边际贡献/解决的内生性问题：当前面板生成（阶段45）未能有效捕捉到行业内其他头部银行金融科技转型所带来的压力/吸收效应。通过采用类似方法的向量相似度矩阵，构建“基于网络关系的同行金融科技滞后项网络工具变量/控制变量”，解决无法识别的竞争溢出或跟随效应引起的内生性问题。

3. 冗余剥离：
在当前 `config.yaml` 存在模块庞大的“词典法情感分析（阶段22_words_tone）”，并硬编码了极为冗长复杂的各类否定词组合以及主观程度副词系数矩阵（>6级、近百种加成倍数）。结合该参考论文的核心成果——在拥有前沿 LLM / Transformer 基座后，复杂的传统硬规则往往因高度脱离上下文、缺乏泛化能力而退化。因此，这种试图用枚举方式解决自然语言曲折性的“伪需求”应当直接剥离，将算力与分析资源全数集中到已经建立的基于 LLM+Embedding 的动态范式和强鲁棒性测试中。


=========================================
【第二部分：项目重构与优化执行计划书】

1. 优先级排布： 
- 速赢项（Quick Wins，极低实施成本极高收益）：强制将阶段21的 Prompt 文本送入层前增设通用化文本重写；直接剔除重度依赖硬写、毫无泛用的词典硬编码分析（阶段22）。
- 核心攻坚项（中实施成本）：计算每一自然年，银行业间基于主要报告/年度相关语料池文本特征得到的余弦Embedding相关度，生成“银行-年份”同行业溢出网络构架。

2. 阶段化执行指令 (SOP)：

阶段一（机制重塑/数据清洗）：
- 指令 1（前因信息剥离）：重构 `00_preprocessing.py` 与 `21_tone_llms.py` 之间的对接数据流。实施事前掩码方案（Ex-ante Masking）——调用现有的 NER 库（或正则表达式库结合已有之 bank_names_file），在准备喂给阶段 21 诸家 LLM 模型的核心 {title} 和 {content} 中，强行将目标银行全部替换为“[目标机构]”，周边共提银行全部替换为“[同业机构X]”。
- 交付物标准：阶段21输入到最终模型的 JSON payload 完全丢失了能推测出具体银行和产品的标志性词汇，仅靠裸新闻动作成分进行分类验证。

阶段二（实证/模型重构与检验）：
- 指令 2（剔除遗留冗余）：在 `config.yaml` 及后续流水线驱动脚本中，全面注销并删除 `tone_words` 相关的基于 IDF / 情感重权重配置模块及对应 `22_words_tone.py` 处理流，并同步移出 45 阶段合并对应字段。
- 指令 3（网络动态映射的注入）：新增执行脚本 `24_embedding_network.py`，调用 OpenAI Text-Embedding 或 T5-XXL（使用 SentenceTransformers）抽取出当前年份对应各家银行的所有金融科技文档嵌入向量均值。
- 交付物标准：输出一个银行间年代动态关联矩阵 `bank_peers_similarity_{year}.parquet`，仅保留相似度位于 Top 1% 或 Cosine Similarity > 0.95 的同业有向边。

阶段三（结论重构）：
- 指令 4（网络调节效应建构）：修改 `45_panel_export_main.py` 以读取该网络矩阵。生成全新的面板变量“同行金融科技渗透滞后溢出项”（Network-Lagged FinTech Attention）。在实证报告分析中着重强调该结构模型是如何通过“彻底遮蔽前瞻性偏差”与“控制竞争者溢出”来双管齐下保障结论可靠性的。

3. 风险预案 (Plan B)： 
- 风险 1：直接无脑通过正则或简单词典进行字符掩盖（Masking）仍然可能有遗漏，导致LLM识别出目标行从而再次激活前瞻偏差。
  -> 预案：若因遗漏引起抽样测试（阶段36此时可转为质量抽检指标）验证一致率低于 0.90，必须迅速退回并引入高效但开源的 `spaCy en_core_web_trf` (翻译转接) 或国内成熟的大型语言 NLP 模型专事进行上下文脱敏操作后再走大模型。
- 风险 2：获取巨量历史新闻记录的完整大文本 Embedding 需要天量调用/请求时间，且引发高频度 Rate Limits 导致流水线崩溃。
  -> 预案：不再给所有零散新闻都计算全文本向量并加权，降维至仅依据“当年该行涉及的前5强综合型官方通稿或年报首段业务简介”调用以萃取其最核心业务相似网络布局。
