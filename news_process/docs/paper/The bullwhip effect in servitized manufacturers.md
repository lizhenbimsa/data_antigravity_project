# 基于《The bullwhip effect in servitized manufacturers》的项目执行计划书

=========================================
## 第一部分：基于参考论文的项目分析与诊断报告

### 1. 范式映射与盲区诊断
**论文核心机制**：Niu 等人 (2025) 的核心贡献在于，在使用文本挖掘（“词袋法”及大语言模型验证）量化企业战略转型（服务化）时，突破了单一维度的度量，将战略动作严格拆分为两类——**“互补型（Complementing）”**与**“替代型（Substituting）”**，并分别揭示了它们对需求波动和企业内部牛鞭效应的异质性作用机制（信息渠道 vs. 效率提升）。

**当前项目盲区**：审查项目 `news_process` 的 `config.yaml` 发现，当前 LLM 语义精筛（阶段 21）中，对金融科技分类（`fintech_category`）使用的是纯技术视角的「底层技术」或「应用场景」。这种分类缺乏经济学战略深度，未能捕捉银行应用金融科技时的**真实战略动机**（是为了修补现有信贷渠道，还是为了彻底重构替代传统业务）。如果将两者混合，在后续实证检验中会导致效应相互抵消（Attenuation Bias），掩盖金融科技对银行风险波动（银行资产负债表层面的“牛鞭效应”）的真实冲击。由于项目在文本抽提的先进性（多 LLM 交叉验证）上已大幅领先论文的词袋法，此时的重点应在于**吸收论文的经济分类逻辑**。

### 2. 实质性改进项（宁缺毋滥）
- **改进 A：在 LLM 标注提示词中引入战略分类维度（互补型 vs. 替代型）**
  - **论文依据**：通过对 10-K 文件的服务化词汇进行互补/替代分类，成功分离了降低需求波动（信息渠道）和缓解内部牛鞭效应（效率渠道）的异质性路径。
  - **预期的边际贡献**：将原有技术标签（`fintech_category`）升级为战略业务标签。可指示 LLM 判断该金融科技新闻属于**“互补增强型”**（如：OCR风控、智能客服，旨在降低传统存贷业务信息不对称）还是**“替代重构型”**（如：开放银行API、纯数字信贷平台，旨在打破或替代传统物理网点渠道）。这将极大丰富 Stage 40 面板数据的经济学含义，可以直接用于探讨不同金融科技战略对信贷波动的异质性影响。

- **改进 B：实证下游匹配“信用波动”（银行牛鞭效应投射）作为核心被解释变量**
  - **论文依据**：创新性地将文本测度的战略指标与企业级运营波动（需求波动与牛鞭效应方差）挂钩。
  - **预期的边际贡献**：超越传统的绩效指标（ROA、NPL）。在面板数据构建完毕后，建议团队提取银行的“信贷供给波动率”或“流动性囤积方差”作为因变量。这在内生性上缓解了业绩绝对值的反向因果问题，且紧扣“技术平滑运营波动”的前沿学术叙事。

### 3. 冗余剥离
- **剔除静态词典及次优模型的冗余计算**：
  从配置可见，虽然主选了 `tone_llms`，但流水线仍预留了 `output_22_words_tone`（词典法）和 `output_23_bert_tone`（BERT 模型）的接口与占位。Niu 等人 (2025) 证明了 GPT-4 可完美验证传统文本分类。项目既然已部署三模型（GPT-5/Gemini/Claude）CoT 架构，其精度和维度理解已呈现代际碾压。建议**彻底剥离并在代码层下线** 22/23 阶段的基于静态词典和早中期 BERT 的情感模块，消除“为对比而对比”的伪需求代码，节省算力，专注 LLM 的多维特征（特别是新增的互补/替代战略分类）抽取。

## 第二部分：项目重构与优化执行计划书

### 1. 优先级排布
- **速赢项（Quick Wins）**：修改 `config.yaml` 中阶段 21 的 LLM Prompt，将原本的 `fintech_category` 替换为互补/替代二维分类，成本极低，面板特征立即翻倍。
- **核心攻坚项**：确保 LLM 能够准确区分银行业由于技术应用带来的“互补”与“替代”边界，需在阶段 32（人工抽样验证）中针对新增的战略分类指标建立黄金标准并计算 Kappa 系数。

### 2. 阶段化执行指令 (SOP)

**阶段一（机制重塑）：升级 LLM 提取框架**
1. **修改配置文件**：编辑 `config.yaml` 的 `tone_llm_processing.prompt_template`。
2. **动作指令**：
   - 定位 `<output_format>`，将 `"fintech_category": "「底层技术」或「应用场景」（false 时填 null）"` 修改为：
     `"fintech_category": "分析该技术对主营业务的冲击性质：选填「互补增强型」(提升现有业务效率/风控) 或「替代重构型」(创造新渠道/新模式替代传统业务)（false 时填 null）"`
   - 在 `<step1_verification>` 补充判断规范，明晰互补与替代的判定边界。
3. **交付物标准**：输出包含新 `fintech_category` 标签的 `21_tone_llms.parquet`。

**阶段二（验证迭代）：一致性检验**
1. **动作指令**：继续执行阶段 32（人类样本对比）。需将人工打标表格新增一列“战略类别”，对新提取的互补/替代类型进行标注。
2. **交付物标准**：阶段 33 分类有效性评估输出新的 Cohen's Kappa 系数，该分类维度的 Kappa 必须达到 0.75 以上。若不达标，触发 Prompt 敏感度测试（阶段 39）进行微调。

**阶段三（模型重构与实证检验）：向下游延伸**
1. **动作指令**：在阶段 41-45 (Bank-Year 面板构建) 中，将金融科技维度的面板变量从单一的得分，切分为 `FT_complementary_score` 和 `FT_substituting_score` 两个独立序列。
2. **验证指令**：在实证跑测部分，引入信贷波动率指标作为Y，复现双重差分或使用现有 Bartik Shift-Share IV 分别对两种分值进行回归，必须体现异质性系数。

### 3. 风险预案 (Plan B)
- **风险卡点**：LLM 无法准确从短篇新闻中区分“互补”和“替代”（因新闻往往夸大其词，且两者的边界在银行业本身较模糊），导致分类一致性评分崩溃。
- **Plan B (降维处理)**：若阶段 33 测试发现 Kappa 系数低于 0.6，必须立即回退。将 Prompt 的分类强制降级为判断**“是否直接面向 C 端客户渠道”**（面向C端替代性强，面向B端/中后台互补性强）。这种降维映射由于具备客观词汇特征（如“APP、客户端”vs“云上数据中心、风控模型”），LLM 判断准确率会飙升，同样能在后续实证中充当强有力的代理变量。
