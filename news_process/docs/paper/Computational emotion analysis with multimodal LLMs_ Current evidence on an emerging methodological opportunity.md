# 业务/学术重构执行计划：基于《Computational emotion analysis with multimodal LLMs》

## 第一部分：基于参考论文的项目分析与诊断报告

**1. 范式映射与盲区诊断**
论文的核心发现揭示了一个关键陷阱与一个方法论机遇：多模态大语言模型（mLLMs）在真实世界场景（如议会辩论录像）中的情感唤醒度（Arousal）测量表现极差且含有严重的人口统计学偏差；但相对地，**基于文本（Text-based）的大模型在情感效价（Sentiment/Valence）提取上具备极高的稳健性和可靠性，彻底碾压传统人工或小模型基准（见论文 Figure 6）**。
针对当前项目现状（`news_process`），诊断如下：
*   **【维持原状】模态壁垒隔离**：本项目坚持基于中文长文本的大模型情感提取（抛弃多模态/视觉捕捉），不仅规避了论文指出的“实验室到荒野（lab-to-field）”表现暴跌这一致命缺陷，同时也最大化了 LLM 在处理文本情绪的比较优势。这一核心架构完全成立，必须**维持原状，严禁盲目向音视频等多模态特征扩展**。
*   **架构盲区识别**：
    1.  **思维链（CoT）坍缩陷阱**：当前 `config.yaml` 阶段 21 使用了强制的“步骤性推理结构（Chain-of-Thought）”。但根据论文 Figure D4 揭示，开启“推理/思考（thinking/reasoning）”模式会导致评分 token 的概率分布强制坍缩（Confidence 强行逼近 1.0），严重损害标量评分的校准度（calibration），使得模型退化为一个生硬的极端硬分类器。
    2.  **情感维度的残缺**：项目目前的硬分类输出唯独保留了“效价（正面/中性/负面）”，却彻底遗漏了情感轮盘模型的核心要素——“唤醒度/冲击烈度（Arousal/Intensity）”（引自论文 Sec 2.3 关于 Russell 情感空间构念的定义）。

**2. 实质性改进项（宁缺毋滥）**
*   **改进 A：引入情感唤醒度（Arousal/Intensity）的连续型量表标定，与效价（Valence）维度的正交解耦**
    *   **标明论文依据**：论文 Section 2.3 与 Figure A3 确凿证明，情绪的“方向（Sentiment/Valence）”与“强度（Arousal/Intensity）”是完全基于不同构念的两个维度（两者在统计上微弱相关 r=0.119）。同时，论文验证了 1-9 九级连续评分法能够极其贴合模型内在对连续特征的表征分布。
    *   **阐述预期的边际贡献/解决的内生性问题**：金融系统中，负面新闻既存在“常态化合规通报（低 Arousal）”，也存在“挤兑/破产等致命黑天鹅危机（高 Arousal）”。为银行新闻增加独立的高颗粒度事件冲击烈度（1-9 分标量）因子，不仅直接解决了仅使用“负面类别”代理带来的同质度量偏误问题（截断偏差），更能在面板回归阶段直接分离日常噪声舆情与极端冲击对银行业务的异质性市场反应。
*   **改进 B：禁用 LLM 的强制过度提示（CoT）结构，摒弃离散标签并还原概率逼近打分机制**
    *   **标明论文依据**：论文 Section 4.1 与 Figure D4 严正得出，“启用 thinking 思维模式反而会降低定量标量评分表现”。不开启深度推理模式的模型（例如关闭 reasoning 并限制温度为 0 的设置）对不确定性的标度表达最为精确和鲁棒。
    *   **阐述预期的边际贡献/解决的内生性问题**：精简 Prompt 中的复杂系统业务规则说明，取消长文本的 `<step>` 分步骤推导逻辑包裹，迫使 LLM 回归预训练的直觉直接在 1-9 标度上输出评级数值。此举能最大程度避免自回归生成的过度对齐陷阱污染，大幅拉升量化指标与实际资产波动标的或绩效之间的线性相关测度。

**3. 冗余剥离**
*   **目标剔除**：**强行剔除阶段 22/23 的全部词典法 (`tone_words`) 与低参数量 BERT (`tone_berts`) 模块代码（包括其极其高昂繁杂的异议词过滤、句末窗口重置、强转折词多级重配规则体系等）。** 
*   **理论依据**：明确指出当前项目阶段中配置的数千个细粒度字典及 5 个预训练小参数 BERT（包括 hw2942, erlangshen 等传统派模型）是偏离主线且价值极低的“伪需求”。论文已透彻证明在文本级 In-context learning（即使在零样本设定下）下，现代 LLM 对情感与语序度量的拟合可靠性远超古典人工特征工程与初级微调模型。保留阶段 22 和阶段 23 属于典型的无益自保，除了徒然增加算力负担、徒增工程并发宕机点之外，在验证时仅会频繁对冲注入干扰红圈噪音（Noise），应当果断全面切断剔除。

## 第二部分：项目重构与优化执行计划书

**1. 优先级排布**
*   **速赢项（Quick Wins）**：
    1. 在 `config.yaml` 中彻底抹除 `sentiment_analysis` 节下关于 `tone_words` 和 `tone_berts` 的全部复杂字典定义及管线激活开关，阻断相关无益分析消耗链。
    2. 改造保留的 LLM 多并发请求引擎端点，严格强制声明不可使用 reasoning 接口层位，确保温度下限锁定（$T=0$）。
*   **核心攻坚项**：
    3. 全面置换并重写 `config.yaml` 内置核心 `prompt_template`，消除伪思维链，更替为要求模型输出 Valence 实数评分及 Arousal 烈度分数双维架构的标量测度范式。
    4. 对后端面板聚合统计流（阶段 40/45）底层统计数据结构进行重构，接纳新维度的实数均值型度量，淘汰低级分类频率加总计算法。

**2. 阶段化执行指令 (SOP)**

*   **阶段一（机制重塑与底层残余剥离）**：
    *   **核心动作指令 1**：清洗缩减 `config.yaml`，剥除涉及 `output_22_words_tone.parquet` 与 `output_23_bert_tone.parquet` 节点的后续引用关联路线。
    *   **核心动作指令 2**：重构 `tone_llm_processing.prompt_template` 指令文本，强制要求大模型直接输出新的极简 JSON Schema 解析表：例如，`{"valence_score": 1, "arousal_score": 9, "is_bank_fintech_news": true}`。效价分数 `1-9`（1=极其严重危害与负面，5=客观陈述零中性，9=极为积极的利好建设）；唤醒度分数 `1-9`（1=常规极其平淡，9=极其剧烈轰动事件并引发极大共振）。
    *   **交付物标准**：瘦身完成、逻辑结构清爽透明的独立 `config.yaml` 配置文件，与严密切配新评分 JSON schema 捕获格式的 `21_tone_llms.py` 代码。

*   **阶段二（实证/模型重构与检验校准）**：
    *   **核心动作指令 1**：在保证所有 LLM 并行池置顶 `temperature=0.0` 及封禁任何潜在 reasoning_format 的严格封锁协议下，满载运行 `21_tone_llms.py` 执行多模型（GPT/Gemini/Claude）背靠背并发标记萃取。
    *   **核心动作指令 2**：重置验证模块基石中的 `34_sentiment_validation`，开展三角交叉验证。将过往因离散类别计算局限而退步选用的 Fleiss' Kappa 或 Krippendorff's α 函数库代码，整体换防至对 Valence 与 Arousal 数值系列序列直接计算 **Intraclass Correlation Coefficient (ICC3k) 系统与 Pearson's r 相关矩阵**，核准测验各个异构模型评分之间的同向内生连续共线紧密度。
    *   **稳健性检验标准**：各个 LLMs 三维组内部，对截面 Valence 效价的 ICC 一致性测算指标必须稳过 0.85 门槛，且对于全新架构衍生的 Arousal 连续烈度评分的 ICC 指标准绳需大于 0.70 作为容忍红线。

*   **阶段三（宏观归因与回归结论重构）**：
    *   **核心动作指令**：基于现今抽提成形的金融科技高维量化分数矩阵，将最终结构性聚合导出面板 (`40_panel_yearly.parquet`) 中极度单薄苍白的基于加总计算的类别总数（如原生单纯计算 `positive_news_count` 频率计数），跨越升级为深度连续异质性时间序列因子群，系统引入生成：
        1.  年份银行别异向均值主体标度（平均事件影响能效）： `mean_valence_score`, `mean_arousal_score`。
        2.  信息穿透的非稳态波动震荡因子：针对 Valence score 在单银行一年度内发酵产生的情绪计算其二阶矩方差或标准差分布（`valence_volatility`），将其作为在传统模型中用作宏观代理资本市场信息不对称风险及恐慌不透明度冲击的前置变量进行计量替代。

**3. 风险预案 (Plan B)**
*   **预判的执行致命卡点（API 黑盒导致 Token 访问拒绝机制）**：本论文（式1）的方法论重度仰靠通过提取截获 LLM 推理接口的最底层的单一备选字典 token sequence 隐藏概率树权重矩阵（即 `Logprobs` 分布集）来计算连带连续标量公式的分布期望：$s_i = \sum p \times scale$，这一操作可极大程度上越权规避硬推断强制分类之陷阱；然而，就现状而言，当今项目管线集成本地化的企业或商用级别的代理中转分发网络接口池（特含 Claude Haiku 等商用节点），在绝大多数商业限制约束下并不原生回吐或并不稳定支持直接针对 `logprobs` 进行深度遍历及截取解码访问操作。
*   **切实可行的底层反制替代方案（Plan B - 伪造伪概率期望）**：必须立即退而求其次果断中止试图请求并硬性介入 `logprobs` 的动作预期。反向转入要求被调用各核心语言模型并在最顶格系统级 Prompt 前置中，指定其直接打印一个落点于区间 1.0 到 9.0 之间、带有单数点位的精准浮点实数代理预期分数（Pseudo-Continuum Decimal Scoring）。随后执行强力收拢，依靠三角矩阵（即强绑组合 GPT-5 + Gemini-3 + Claude 4.5）计算此三大异构核心模型的该浮点向量之平行算术平均值。通过“大数样本强制纠偏定律”将其作为在缺失真正底层 Token 隐藏期望几率的前提下的一项核心变通代偿算法，将其结果直接烙定为最终无偏抽提逼近逼近值输出。这一策略足以在工程层级强行抹平因离散输出标尺先天决定的硬性阶跃突变量舍入误差（Rounding Error），确保其在随后的所有经济计量线性操作面上具备完全同等效力的微分可微性数学特征。
