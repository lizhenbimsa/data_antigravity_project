# 基于参考论文《中国企业数字技术风险暴露对企业价值的影响》的评估与优化执行计划

## 第一部分：基于参考论文的项目分析与诊断报告

### 1. 范式映射与盲区诊断
**核心机制提炼**：
参考论文强调数字技术风险的**双面性与隐蔽性**，通过大语言模型分别捕捉文本中的“风险暴露点”（负面最大值）与“风险防范能力”（正面平均值）作差，衡量最终风险暴露程度；此外，论文的实证高潮并非仅仅验证技术风险对企业估值（Tobin's Q）的负向影响，而是明确提出并验证了基于数字基础设施互联性的**供应链网络溢出效应**。

**盲区诊断**：
当前项目（`news_process`）主要依赖于 LLMs （`21_tone_llms.py`）和词典（`22_tone_words.py`）对商业银行金融科技新闻的“通用情感（正面/中性/负面）”进行判定。
- **测量盲区**：通用负面情感无法有效剥离出纯正的“技术操作风险”（如系统瘫痪、数据泄露、黑客攻击），容易与“监管处罚”、“业绩下滑”等非技术负面舆情混淆。目前的一维判断缺失了对企业“防御性应对/安全修复”叙事的度量。
- **机制检验盲区**：当前面板分析规划（包含政策 DID 和 Bartik IV）主要针对个体的价值评估。银行业虽然不存在物理制造业的上下游供应链，但高度依赖**同业资金网络或信贷关联网络**。当前项目缺乏从网络外溢视角探讨金融科技风险的跨行传染机制考察，这是一个明显的脱轨。

### 2. 实质性改进项（宁缺毋滥）
- **改进 A：基于大模型提取专门维度的“数字技术风险暴露”度量新指标**
  - **[具体修改建议]**：修改 `config.yaml` 中的 LLM Prompt 结构。不仅判定是否有金融科技主题及正负面，针对负面新闻进一步细分提取是否包含“数据安全风险（Data_Risk）”或“网络安全风险（Cyber_Risk）”，同时让大模型量化打分“风险严重概率估值 (0~1)”并提取出“风险防范能力 (0~1)”。
  - **[标明论文依据]**：论文采用 `风险敞口 = 负面文本负情感最高概率 - 正面文本防范情感平均概率` 作为测量基准。
  - **[预期边际贡献]**：在通用情感外专门分离出技术风险特定变量，精准对接“操作风险管控”理论，极大提升该维度的研究纯度和实证可信度、解决内生性混淆。

- **改进 B：构建“同业网络/资金网络”维度的技术风险外溢检验**
  - **[具体修改建议]**：在 `45_panel_export_main.py` 及之后的实证脚本中加入“银行间传染”的检验。收集银行间的同业存单、同业拆借或共同股东重叠网络矩阵（Network Adjacency Matrix）。衡量焦点金融机构的技术风险发生对一级或二级同行网络企业绩效和债务融资成本的外溢影响。
  - **[标明论文依据]**：假说1及表6供应链外溢（一级客户/供应商关联）分析。
  - **[预期边际贡献]**：将实体供应链逻辑平移重构为银行业的网络外部性（同业系统性风险冲击传染机制），这符合顶刊金融研究在“技术风险放大效应”主题上的偏好。

- **改进 C：引入同行业技术风险的国际溢出工具变量（IV_US）**
  - **[具体修改建议]**：扩充现存的 Bartik IV 方法集。构建“美国上市银行业或海外成熟市场同期的类似金融数字技术风险程度”作为中国对应机构技术风险的工具变量。
  - **[标明论文依据]**：论文第十页利用世界范围内发达国家同行业面临的数字技术风险建立同源工具变量以缓解内生性误差。
  - **[预期的边际贡献]**：引入与本国无直接商业往来但技术特征高度同频的外生外溢 Shock，规避国内层面由于商业决策反馈导致的变量内生性。

### 3. 冗余剥离
- **关于稳健性验证（坚决维持原状）**：当前项目的窗口半径敏感性测试、Krippendorff’s α 检验乃至 Prompt 敏感度检验等极度详实，**逻辑高度自洽且全方位优于该中文学术参考论文的检验水平，坚决维持原状，无需剥离**；
- **需要剥离或降级的伪需求**：现存流水线计划生成的基于三级地址的纯地理注意力指数（`compute_attention_index` 等空间集聚分析）用于一般的企业技术溢出可以解释，但在讨论具体到瞬时爆发性的“底层技术安全或网络攻击暴露”问题时，物理空间的作用往往远小于网络、同业关系的关联。在这项衍生研究中，直接切入资金或数字设施网络更为妥当，应降级纯地理邻近维度的权重。

## 第二部分：项目重构与优化执行计划书

### 1. 优先级排布
- **速赢项（Quick Wins）**：修改更新 `config.yaml` 中 LLM 的提示词结构（Prompt）与 JSON 输出规范。只需调整让 LLM 同步提取特定的技术风险（数据/网络）类型及防御措施强度，即可无缝利用现有成熟的并行双轨请求工程落地提取新指标。
- **核心攻坚项**：同业连结矩阵（信贷网络或持股网络）的收集与测算模型重构；对标的美国银行级数字安全风险工具变量（IV）的高频数据抓取与构建。

### 2. 阶段化执行指令 (SOP)

#### 阶段一（机制重塑与数据清洗：特定指标分离）
- **核心动作指令**：
  在 `config.yaml` 内更新 `prompt_template` 和 `<output_format>`。
- **明确交付物标准**：
  (1) 新的输出 JSON Schema 须新增三个字段：`risk_category` ("数据安全", "网络攻击", "无"), `risk_severity` (0.0~1.0), `mitigation_effort` (0.0~1.0 预防或事后修复机制)。
  (2) `21_tone_llms.py` 代码中补充对应的解析逻辑，并直接衍生出 `Tech_Risk_Exposure_Score` 的结构化列进行保存。

#### 阶段二（实证模型重构与检验：网络关联面板拓展）
- **核心动作指令**：
  搭建银行同业业务空间/网络面板数据矩阵，进行技术溢出加权拟合。
- **稳健性检验标准**：
  在生成面板 `45_panel_export_main.py` 或新增 `46_panel_spillover.py` 阶段：
  (1) 从外部导入各大商业银行（Bank）年度空间或持股邻接矩阵 $W$；
  (2) 回归中计算构建空间滞后项变量（同行溢出变量），用于检验靶向银行的技术风险暴露怎样影响其一级资金方或关联方的 Tobin's Q，替换原本仅依靠自解释框架的检验模型。

#### 阶段三（工具变量结论重构）
- **核心动作指令**：
  根据论文“美国同行业数字技术风险暴露法”构建工具变量（IV），执行内生性两阶段解决回归。
- **明确执行标准**：
  在 `44_panel_iv_did.py` 阶段或者新建模块中：采集同期美国大型银行群体（如 JPM, BoA, Citi）的新闻数据集或其财报 MD&A 的 FinBERT 计算值，匹配到年度/季度面板，进行 2SLS 两阶段最小二乘回归。

### 3. 风险预案 (Plan B)
- **致命卡点 A**：中国银行业的“同业拆借高频数据网络矩阵”由于监管信息保密，实证学者个人极难获取全样本量化真实资金往来。
  - **替代方案 (Plan B)**：放弃具体的拆借网络，转为直接利用上市公司年报披露的前十大股东、或公募基金重仓信息提取出“共有机构投资者关联网络（Common Institutional Ownership Network）”来表征紧邻的外溢网络；或通过银行业的应用APP接口共享、底层技术合作财报重叠词作为其替代连结强度向量。
- **致命卡点 B**：收集和计算全美的银行业技术风险指标（跨国同业 IV）需要大量的接口工作并具有滞后难度。
  - **替代方案 (Plan B)**：不向全球拓展，转为调用国际级别的客观宏观科技威胁频度指标（例如通过权威漏洞库 NVD 中公布的年级别 CVE 重大网络漏洞爆炸数量），再与受分析样本银行上一年度“IT/信息化团队规模权重”做宏观微观交乘构造互动工具变量（Shift-share IV变形）进行有效平替。
