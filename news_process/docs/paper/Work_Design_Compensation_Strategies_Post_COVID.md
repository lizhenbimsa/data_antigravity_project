# 第一部分：基于参考论文的项目分析与诊断报告

## 1. 范式映射与盲区诊断

### 1.1 论文核心机制提炼

Ge et al. (2026) 的方法论内核可提炼为以下三层：

| 层次 | 论文做法 | 核心创新 |
|------|---------|---------|
| **L1: LLM 多维评分框架** | 用 GPT-4o-mini 从岗位描述文本中同时评估 6 个工作设计维度（skill variety, task identity, task significance, autonomy, feedback 各 5 级 Likert + WFH 二值），单次 Prompt 返回结构化评分向量 | 将 LLM 从"分类器"升级为"多维连续评分器"，通过 Likert 量表实现**细粒度、可回归的连续度量** |
| **L2: 构建效度三角验证** | ① 理论锚定的内容效度（Hackman & Oldham 1976 定义嵌入 Prompt）→ ② 30 名专家独立评分的收敛效度（ICC(1) 0.33–0.57, ICC(2) 0.94–0.98, Pearson r 0.56–0.84）→ ③ 外部基准效度（与 Dingel & Neiman 2020 WFH 基准 74.31% 一致率） | **三层效度链**使 LLM 评分获得心理测量学意义上的效度认证 |
| **L3: 中介传导与调节边界** | COVID Case → Work Design Characteristics → Salary（Bootstrap 中介）；Nonroutineness 调节中介路径强度（条件间接效应）；薪酬结构分解（绩效薪酬、期权、培训、补贴、保险的异质性响应） | **从"浅层描述"到"机制分解"**——外部冲击如何经由工作设计传导至薪酬结构的完整因果链 |

### 1.2 当前项目的范式对标

| 维度 | 当前项目现状 | 与论文对标的落差 | 严重性 |
|------|------------|---------------|--------|
| **LLM 评分粒度** | 二值验证（true/false）+ 三分类情感（正面/中性/负面） | 论文展示 LLM 可在单次 Prompt 中可靠输出 5 级 Likert 连续评分，项目仅利用了 LLM 能力的冰山一角 | ⚠️ 中等 |
| **构建效度验证链** | 有人工标注一致性（Cohen's κ）、Krippendorff's α、Prompt 敏感度测试 | 缺少 ICC(1)/ICC(2) 单评分者/均值可靠性分解，缺少外部基准效度验证（如与 CSMAR 分析师情感评级对标） | ⚠️ 中等 |
| **多维评分能力** | LLM Prompt 仅输出单一情感标签 + 置信度 | 未利用 LLM 的多维同时评分能力来区分不同维度（如创新性、风险性、监管合规性等子维度） | 🔴 核心盲区 |
| **情感的连续度量** | 三分类离散标签（+1/0/-1），置信度加权为 [-1, +1] 连续值 | 论文直接使用 5 级Likert 评分（1–5），信息损失更小；当前项目的"离散 × 置信度"是间接连续化，不如直接连续评分精确 | ⚠️ 中等 |
| **多方法集成** | 3 LLM + 5 词典 + 5 BERT = 13 模型三角验证 | 论文仅用单 LLM（GPT-4o-mini），当前项目**已大幅超越** | ✅ 优于论文 |
| **双轨道架构** | Full-text + Context-track 双轨并行 | 论文无此设计，当前项目**已大幅超越** | ✅ 优于论文 |
| **实体级归因** | Aho-Corasick 自动机 + 句级窗口 + O(N log N) 区间合并 | 论文无此需求（岗位帖 = 单实体），当前项目**已完整解决** | ✅ 优于论文 |

### 1.3 核心诊断结论

> **项目在 LLM 工程化部署（多模型集成、双轨道、并发控制）上已远超论文水平。**
>
> **真实落差集中在：LLM 的"多维连续评分"能力未被开发，以及构建效度验证链的 ICC 层缺失。**

## 2. 实质性改进项（宁缺毋滥）

### 改进 A：引入 LLM 多维 Likert 评分框架——情感子维度分解

- **具体修改建议**：在现有 LLM Prompt（`tone_llm_processing.prompt_template`）中，将情感判定从当前的单一"正面/中性/负面"三分类，扩展为多维 Likert 评分向量。具体建议增加以下可回归的子维度（均为 1–5 Likert 量表）：

  | 子维度 | 定义 | 理论锚定 |
  |--------|-----|---------|
  | `innovation_tone` | 对目标银行金融科技**创新能力与技术突破**的评价倾向 | 对应论文的 skill variety 维度思路 |
  | `risk_tone` | 对目标银行金融科技**风险暴露与安全隐患**的评价倾向 | 对应论文的 task significance → 社会影响映射 |
  | `regulatory_tone` | **监管合规性**相关内容的情感倾向 | 金融文本特有，对应 autonomy → 监管约束对偶 |
  | `strategic_tone` | 对目标银行金融科技**战略部署与长期布局**的评价 | 对应论文的 task identity → 完整性/前瞻性 |
  | `market_competitiveness` | 对目标银行在金融科技领域**市场竞争力**的评估 | 对应论文的 feedback → 市场信号 |

- **论文依据**：Ge et al. (2026) §3.2 明确验证了 GPT-4o-mini 在单次 Prompt 中对 6 个理论维度的 Likert 评分具有高度内容效度和收敛效度（expert 相关 r = 0.56–0.84），证明 LLM 完全有能力超越简单分类任务。

- **预期边际贡献**：
  1. 从"单一情感信号"升级为"多维度情感光谱"，使下游回归可区分"创新正面但风险负面"的复杂新闻报道
  2. 实现情感的**维度化分解**——银行金融科技的哪个维度驱动了市场反应？当前不可能回答此问题
  3. 连续 Likert 评分相较三分类离散标签，**信息保留率**更高，回归系数估计更精确（降低衰减偏误，呼应 Shapiro et al. 2022, JoE 的测量误差分析）

### 改进 B：引入 ICC 评分者可靠性分析层——补全构建效度链

- **具体修改建议**：在 `32_news_llms_human.py` 人工验证模块中，增加 ICC(1) 和 ICC(2) 的计算逻辑。

  - **ICC(1)**（单评分者可靠性）：度量单个评分者（此处为单个 LLM 模型或单个人工编码员）的判断在多大程度上与群体一致
  - **ICC(2)**（均值可靠性）：度量 k 个评分者均值的可靠性（此处适用于 3-LLM 多数投票均值）

  计算范式：双向随机模型（two-way random），与论文 §3.4.2 完全一致。

  **通过阈值**（McGraw & Wong 1996; Woehr et al. 2015）：
  - ICC(1) ≥ 0.25（large effect size threshold）
  - ICC(2) ≥ 0.70（acceptable reliability of aggregated ratings）

- **论文依据**：Ge et al. (2026) §3.4.2 报告 ICC(1) 范围 0.33–0.57（全部 ≥ 0.25 large 阈值），ICC(2) 范围 0.94–0.98（全部 ≥ 0.70），这一标准在 HRM/管理学顶刊中已成为 LLM 评分效度的**准入门槛**。

- **预期边际贡献**：
  1. 当前项目仅报告 Cohen's κ（评分者对一致性），ICC 体系从**方差分解**角度提供互补信息——即"评分变异中有多大比例归因于真实差异"
  2. ICC(2) 直接量化了 3-LLM 多数投票共识的可靠性，为三角验证的**统计基础**提供严格检验
  3. 满足管理学/金融学顶刊对 LLM 评分方法的最新效度要求（Carlson & Burbano 2026, SMJ）

### 改进 C：外部基准收敛效度验证

- **具体修改建议**：在验证模块中新增一项外部基准收敛效度检验。选取以下至少一项外部基准：

  | 外部基准 | 可操作性 | 对标逻辑 |
  |----------|---------|---------|
  | CSMAR 分析师情感评级 | ⭐⭐⭐ 高 | 将 LLM 生成的银行金融科技情感与同期分析师对同一银行的覆盖评级对比 |
  | Wind 金融科技主题指数 | ⭐⭐ 中 | 将聚合后的行业级情感指标与 Wind 金融科技主题指数走势对比 |
  | 银行年报金融科技段落情感 | ⭐⭐ 中 | 年报文本（已结构化）作为非新闻源的独立参照 |

- **论文依据**：Ge et al. (2026) §3.4.2 将 LLM 生成的 WFH 评分与 Dingel & Neiman (2020) 公开学术基准对标（74.31% 一致率），证明外部基准检验的可行性和必要性。

- **预期边际贡献**：证明新闻情感指标不是 LLM 的"幻觉"，而是与独立信息源的真实信号高度一致，从根本上回应审稿人对 LLM 构建效度的质疑。

## 3. 冗余剥离

经逐模块扫描，**当前项目无需剔除任何模块**。理由如下：

| 模块 | 评估 | 结论 |
|------|------|------|
| 三方法情感分析 (LLM/词典/BERT) | 论文仅用单 LLM，但本项目的多方法三角验证是更高标准 | **维持原状** |
| 双轨道架构 (Full/Ctx) | 论文无此设计，但本项目解决的多实体归因问题更复杂 | **维持原状** |
| 29 套 Bartik IV | 论文无此需求，但本项目的因果识别体系已经自洽 | **维持原状** |
| Prompt 敏感度测试 (39) | 论文引用了 Carlson & Burbano (2025)，本项目已实现 | **维持原状** |
| Entity Masking 测试 (36) | 论文未涉及，但对多实体情感归因至关重要 | **维持原状** |
| 距离衰减敏感性 (38b) | 论文未涉及，但作为上下文窗口半径的稳健性检验有独立价值 | **维持原状** |

> **结论**：当前项目架构精简且逻辑自洽，不存在需要剥离的伪需求模块。

## 2. 阶段化执行指令 (SOP)

### 阶段一：ICC 评分者可靠性分析嵌入（P0 速赢项）

**目标**：在现有人工验证/三角验证体系中补充 ICC(1)/ICC(2) 可靠性指标。

**动作指令**：

1. **修改 `34_tone_validation.py`**（或新建独立验证函数）：
   - 在三角验证报告中新增 ICC 计算模块
   - 将 3 个 LLM 模型（gpt5nano, gemini3, claude4h）的逐条情感评分视为 3 个"评分者"
   - 使用 `pingouin.intraclass_corr()` 计算双向随机 ICC(1) 和 ICC(2)
   - 分别对 `_full` 和 `_ctx` 轨道独立计算

2. **输入数据**：`21_tone_llms_full.parquet` 中已包含 `{short}_score_full` 和 `{short}_score_ctx` 列

3. **计算范式**：
   ```
   ICC 类型：ICC(2,1) — 双向随机模型，单度量
   目标矩阵：N_articles × 3_models 的评分矩阵
   对 Likert 评分（若实施改进 A）按原值计算
   对三分类情感（+1/0/-1）按有序数值计算
   ```

4. **通过标准**：
   - ICC(1) ≥ 0.25 → 单模型评分具有至少"大效应"可靠性
   - ICC(2) ≥ 0.70 → 多模型均值聚合达到"可接受"可靠性

5. **交付物**：
   - 日志中输出 ICC(1), ICC(2), 95% CI
   - 保存至 `eval_reports/34_icc_reliability.csv`
   - 若 ICC(2) < 0.70，触发警告并建议增加模型数量

**交付标准**：ICC 报告可直接引用于论文方法论章节的"Construct Validity"段落。

### 阶段二：多维 Likert 评分框架（P1 核心攻坚项）

**目标**：将 LLM 从"三分类情感分类器"升级为"多维连续评分器"。

**动作指令**：

1. **Prompt 重构**（修改 `config.yaml` → `prompt_template`）：
   - 保留现有的阶段一（语义真伪精筛）和阶段二（三分类情感判定）不变
   - **新增阶段三**：多维 Likert 评分（仅当阶段一判定为 true 时执行）
   - 输出格式在现有 JSON 中增加 `dimension_scores` 字段：
     ```json
     {
       "is_bank_fintech_news": true,
       "sentiment": "正面",
       "dimension_scores": {
         "innovation_tone": 4,
         "risk_tone": 2,
         "regulatory_tone": 3,
         "strategic_tone": 5,
         "market_competitiveness": 4
       }
     }
     ```
   - 每个维度附理论定义和评分锚点（1=极低, 2=较低, 3=中等, 4=较高, 5=极高）
   - 参照论文 §3.2 的 Prompt 设计原则：角色提示 + 少样本示例 + 构建定义嵌入

2. **解析适配**（修改 `21_tone_llms.py` → `parse_json_response` 和 `_aggregate_track`）：
   - 从 JSON 响应中提取 `dimension_scores` 字典
   - 对每个维度执行多模型多数投票（取中位数而非众数，因为是有序量表）
   - 生成列名规范：`{dimension}_{track}`，如 `innovation_tone_full`、`risk_tone_ctx`

3. **下游管道适配**（修改 `41_panel_encode_aggregate.py`）：
   - 在聚合字典 `build_aggregation_dict()` 中追加 5 个维度 × 2 个轨道 × 3 种聚合（mean/std/sum）
   - 在 Stata 导出的 `STATA_LABELS` 中追加变量标签

4. **效度验证**：
   - 新增专家评分实验：随机抽样 50 条新闻，由 ≥ 10 名金融学背景评分者对 5 个维度评分
   - 计算 LLM 评分与专家评分的 Pearson 相关系数和 ICC
   - 收敛效度通过标准：r ≥ 0.50, p < 0.001（与论文 §3.4.2 一致）

**交付物**：
- 修改后的 `config.yaml` Prompt 模板
- 适配后的 `21_tone_llms.py` 解析逻辑
- 适配后的 `41_panel_encode_aggregate.py` 聚合字典
- 效度验证报告 `eval_reports/likert_convergent_validity.csv`

**交付标准**：
- 5 个维度的 ICC(2) ≥ 0.70
- LLM 与专家评分的 Pearson r ≥ 0.50（至少 4/5 维度达标）
- 下游 Bank×Year 面板中新增 ≥ 30 个多维情感变量

### 阶段三：外部基准收敛效度验证（P2 稳健性增强项）

**目标**：通过独立外部数据源验证 LLM 生成的情感指标并非"幻觉"。

**动作指令**：

## 3. 风险预案 (Plan B)

### 风险一：多维 Likert 评分质量不达标

**症状**：LLM 对某些维度的评分方差极低（几乎所有新闻的 `regulatory_tone` 都打 3），或维度间过度共线性（r > 0.90）。

**预案**：
- **方案 B1（维度精简）**：将 5 个维度精简为 3 个（innovation_tone, risk_tone, strategic_tone），优先保留方差最大、共线性最低的维度
- **方案 B2（主成分提取）**：对 5 维 Likert 矩阵执行 PCA，提取前 2–3 个主成分，保留可解释方差 ≥ 70% 的成分作为综合指标
- **方案 B3（回退三分类）**：若所有维度的 ICC(2) < 0.50，表明 LLM 对多维评分尚不可靠，放弃此改进，维持现有三分类方案不受影响

### 风险二：ICC 计算发现三模型一致性不足

**症状**：ICC(2) < 0.70，表明 3-LLM 多数投票的聚合可靠性不满足学术标准。

**预案**：
- **方案 B1（增加模型数）**：将模型数从 3 增至 5（增加 Qwen-2.5 和 DeepSeek-V3），ICC(2) 随 k 增大单调递增
- **方案 B2（置信度加权替代多数投票）**：放弃多数投票，改用各模型自报的 `sentiment_confidence` 作为加权权重的软投票，降低不可靠模型的投票权重
- **方案 B3（报告为已知局限）**：若 ICC(1) ≥ 0.10（medium effect），仍可在论文中报告为"单模型可靠性达到中等水平，但聚合可靠性有待提升"——这比不报告 ICC 更有学术说服力

### 风险三：外部基准数据不可得

**症状**：目标时间窗口内 CSMAR 分析师评级数据覆盖率过低或匹配率不足。

**预案**：
- **方案 B1（事件研究替代）**：使用银行层面重大金融科技事件（如 DCEP 试点公告、App 上线日期）作为事件基准，检验事件前后 LLM 情感是否显著变化（t 检验），间接验证度量有效性
- **方案 B2（年报交叉验证）**：从银行年报中提取金融科技段落，使用相同 LLM 评分框架独立评分，计算新闻情感与年报情感的 Bank×Year 级相关性
- **方案 B3（内部一致性替代）**：改用 Split-half 方法——将每个 Bank×Year 的新闻随机二等分，分别计算情感均值，检验两半的 Pearson 相关和 Spearman-Brown 校正可靠性 ≥ 0.80
