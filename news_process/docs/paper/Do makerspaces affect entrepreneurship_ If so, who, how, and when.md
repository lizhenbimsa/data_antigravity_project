# 论文导向的系统重构与执行计划书

=========================================
第一部分：基于参考论文的项目分析与诊断报告

1. 范式映射与盲区诊断：
Bao (2024) 在评估创客空间对创业的影响机理时，通过引入两大创新度量范式剖析动态过程：第一，通过纵向追踪项目的“更新迭代次数 (Number of Updates)”捕捉资源供给带来的低成本试错与创新实验机制 (Experimentation)；第二，使用“文本相似度 (Text Similarity)”刻画因地理或场景临近引发的知识溢出网络效用 (Knowledge Spillovers)。
反观本项目的金融科技新闻数据管道，现有逻辑仅停留在将新闻进行简单的静态分类与定点的情感计分上。在应对“银行金融科技创新”这种典型的过程性、网络化事件时，当前设计存在明显的理论落差与实证盲区——缺乏对同一个金融科技举措从概念部署到应用落地的生命周期（迭代频度）刻画，亦无法识别创新战略在同行与同一区域间的扩散与趋同特征。这难以区分出到底是实质性的底层技术研发投入，抑或仅仅是空泛的“AI跟风披露”与“漂绿式科技声明”。

2. 实质性改进项（宁缺毋滥）：
- 改进 A：构建“创新迭代试错频频度 (Iterative Experimentation)” 指数 
  -> [论文依据]：Bao (2024) 第 5.2.2 节使用随时间推移的 Number of Updates 来代理资源通道带来的试错增加；
  -> [边际贡献]：利用 LLM 追踪并在面板构建时对指向一致性项目的历时新闻报道频率进行聚合。以此作为商业银行在金融科技领域实质性试验力度的代理指标，根本上治理象征性披露（Symbolic Disclosure）引发的内生性问题，确保抓取的特征是真实的业务纵深的进化，而非营销造势的“一锤子买卖”。

- 改进 B：引入“区域同业知识溢出与技术趋同性 (Knowledge Spillovers)” 测度网络
  -> [论文依据]：Bao (2024) 测试社会促进通道机制时，使用横截面 Text Similarity 验证了主体间因物理/机制邻近性引发的学习反馈网络；
  -> [边际贡献]：使用轻量级的 Sentence-BERT 对同一省份或核心竞对银行释放的科技创新新闻计算两两间的内容语义相似度。提供全新的衡量知识外溢、同行竞争效仿程度的代理机制，大幅扩宽原有的基于统计词汇密度的控制变量池，为多维固定效应验证提供更有穿透力的实证依据。

- 改进 C：增配情景特征库刻画首创性与跟随意图 (Intentional vs. Accidental/Follower)
  -> [论文依据]：论文第 5.1.2 节利用文本特征来标记创业意欲为“Intentional”抑或“Accidental”；
  -> [边际贡献]：通过增加重写 21 步骤 LLM 思维链指令，分析银行部署特定技术的措辞（是主动牵头自研，还是被动迎合行业风口或监管指标），有效分离高质量的首创突破和低效的同质化模仿。

3. 冗余剥离：
- 剥离伪需求模块：直接剔除落后且冗余的“词典法情感计算 (`22_tone_words.py`)”与“传统 BERT 情感分类 (`23_tone_berts.py`)”子模块。
基于词表（无论是否 TF-IDF 加权）及小规模预训练 BERT 已无法适应极具动态语义的当代复杂财经文本挑战。当前 `config.yaml` 已经被人工移除关联触发节点。鉴于大语言模型推理已配置充分（支持 CoT 三角验证），在代码生态中保留传统字典维护仅仅是算力与代码运维的双重内耗，建议物理清理与其相关的所有硬编码逻辑。

第二部分：项目重构与优化执行计划书

1. 优先级排布：
- 速赢项（Quick Wins）：“21步管道 LLM 指令扩展”以及“冗余基线脚本清理”，属于极低实施成本、立竿见影的代码瘦身及标签扩容项。
- 核心攻坚项：“动态文本相似度量引擎构建”与“纵向迭代追踪（Bank-Year Panel 数据重塑）”，涉及大规模的向量编码以及跨时序面板计算，是实现顶级实证要求质量壁垒的核心所在。

2. 阶段化执行指令 (SOP)：

阶段一（机制重塑/数据清洗）：
- 指令 1（精兵简政）：切底删除 `22_tone_words.py`、`23_tone_berts.py` 脚本，以及 `config/sentiment_dicts` 遗留目录资源。在配置总线上仅保留唯一的 LLM 高级评测入口。
- 指令 2（LLM标签赋能）：重构 `21_tone_llms.py` 中 Unified CoT 提示词定义。要求 JSON 强制返回三个新增维度："innovation_intent" (标识主动先锋或被动跟随)、"project_stage" (标识概念设计或产品迭代落地)。
交付物标准：输出只含有 `output_21_tone_llms.parquet` 一种高质量处理管道的流水线，并完成附加验证字段。

阶段二（实证/模型重构与检验）：
- 指令 1（新建溢出网络算子）：建立专设模块 `24_knowledge_spillovers.py`。部署经金融测试集微调的句子嵌入模型（如 BGE 或 Sentence-BERT的财经向版本），以省市区间为限定池，对时间窗口（T期及 T-1期）内所有新出现的科技事件进行逐对向量（Pairwise Cosine Similarity）估算。
- 指令 2（合成聚类结果）：生成该特定银行该周期的 Text-Similarity 相似度距离均值和最高值。该模块应能利用并行加速。
稳健性检验标准：该数值需保证能和该银行早于窗口前的高密度事件产生明显的数据降解隔离。

阶段三（结论重构）：
- 指令 1（面板架构融合合并）：修改原有的 `41`、`42` 及 `45` 等数据面板汇集阶段。向 Bank-Year 年度基础底表融入三大新型指标群：
  i) 年均跟风模仿率与独立自研水平;
  ii) 同业科技战略相似性/聚拢偏差度 (Spillover Index);
  iii) 单一关联重大倡议后续更新频次的平均跨度时长 (Experimentation Length)。
这些将被送入面板回归和内生性（DID/IV）检验机制进行回归。

3. 风险预案 (Plan B)：
- 致命卡点：所有同业横向 Pairwise Text-Similarity 如果新闻总量逾十万条，将带来严重的 $O(N^2)$ 计算瓶颈以及高昂的推流成本。
- 替代方案（Plan B）：不采取全区域或全局文本配对，而是使用无监督主题聚类法（例如 HDBSCAN 等），计算某一条银行的新闻特征向量是否掉落在当前周期已被高光标注的热门簇（热门业务/模型库）内部，使用核心簇的距离作为相似性代理变量，将时间与空间复杂度降至一维数组比较。
