# 第一部分：基于参考论文的项目分析与诊断报告

## 1. 范式映射与盲区诊断

### 1.1 论文核心机制提炼

胡俊(2024)的核心范式可拆解为**四大机制模块**：

| 机制编号 | 论文核心机制 | 方法论要点 | 当前项目对标状态 |
|:---:|:---|:---|:---:|
| **M-1** | **双词库构建** (银行名称 + 金融科技关键词) | NER → 预训练词向量扩充 → LDA 主题筛选 → 773个关键词 | ✅ **已实现且超越** |
| **M-2** | **银行-新闻匹配** (命名变体关联) | 1566家银行 × 7713个命名变体 → 80%排他性匹配规则 | ✅ **已实现且强化** |
| **M-3** | **金融科技指数构建** (三维词频标准化) | FT = FTWORD/NEWS, 分战略理念/底层技术/产品服务三维子指数 | ⚠️ **部分实现** |
| **M-4** | **赋能效果检验** (中介效应 + 普惠金融) | 运营/服务/风控→ROA中介; 贷款规模↑但利率不降→"普而不惠" | ⚠️ **存在落差** |

### 1.2 详细对标分析

#### ✅ M-1: 词库构建 — 维持原状

| 对标维度 | 论文做法 | 当前项目做法 | 判定 |
|:---|:---|:---|:---:|
| 金融科技词库规模 | 773个关键词(人工+预训练词向量扩充) | `fintech_dict.json` + Aho-Corasick自动机 | **项目优于论文** |
| 词库扩充方法 | 腾讯AI Lab开源词向量, 余弦相似度>0.8 | 已有词库 + 37_dict_coverage_audit.py 覆盖率审计 | **等价+审计** |
| 银行名称词库 | 银保监会法人名单 + NER + 人工判断 → 7713变体 | `bank_names.json` + NER排除模式 + 短名歧义消解 | **项目更严谨** |

**结论: 维持原状。** 当前项目在词库构建方面已超越论文标准，无需修改。

#### ✅ M-2: 银行-新闻匹配 — 维持原状

| 对标维度 | 论文做法 | 当前项目做法 | 判定 |
|:---|:---|:---|:---:|
| 匹配算法 | 未详述(推测Python字符串匹配) | Aho-Corasick O(n)线性扫描 | **项目更高效** |
| 排他性规则 | 80%出现次数阈值 | 上下半分布 + 标题匹配 + 最少出现次数 + 否定模式排除 | **项目更严谨** |
| 多银行处理 | 简单提及(80%排他) | Firm-Document展开(Hassan 2019 QJE) + mention_density加权 | **项目远超论文** |
| 假阳性控制 | 未提及 | 否定模式AC自动机 + 短名歧义消解 + 上下文窗口 | **项目独有** |

**结论: 维持原状。** 项目的匹配精度和方法论严谨度远超论文。

#### ⚠️ M-3: 金融科技指数构建 — 存在可改进空间

| 对标维度 | 论文做法 | 当前项目做法 | 差距分析 |
|:---|:---|:---|:---|
| **指数定义** | FT = FTWORD/NEWS (词频/新闻总条数) | `fintech_distinct_keywords`计数 → LLM验证 → 情感三角 | 项目用LLM替代词频, **方向正确但不同范式** |
| **三维子指数** | 战略理念/底层技术/产品服务 三个独立子指数 | `fintech_category` 仅二分(底层技术/应用场景) | **缺少"战略理念"维度** |
| **标准化** | FTWORD/NEWS 控制银行"曝光"差异 | `n_articles`, `ln_news_coverage` 已有 | ⚠️ 可补充标准化指标 |
| **LDA主题筛选** | 预设20/30主题 → 概率最大两主题 → 人工判定 | LLM CoT语义精筛(验证+情感双阶段) | **项目用LLM替代LDA, 更先进** |

> **关键分歧:** 论文的`fintech_category`是三维(战略理念/底层技术/产品服务)，当前项目仅有二维(底层技术/应用场景)。"战略理念"维度在论文中独立贡献了子指数并参与回归。但考虑到当前项目的LLM分类已将"战略理念"类内容自然纳入"应用场景"范畴，且LLM的语义理解能力远强于关键词三分法，**此项不构成致命缺陷**，但可作为稳健性检验的补充维度。

#### ⚠️ M-4: 赋能效果检验 — 需重点关注

| 对标维度 | 论文做法 | 当前项目做法 | 差距分析 |
|:---|:---|:---|:---|
| **中介效应通道** | 运营能力(成本收入比)→ROA, 服务能力(手续费占比)→ROA, 风控能力(不良贷款率)→ROA | 无独立中介效应检验模块 | ⚠️ **不涉及**, 属面板下游Stata检验 |
| **普惠金融检验** | 贷款规模↑, 贷款利率↑ → "普而不惠" | 未设计对应变量 | ⚠️ **不涉及**, 属面板下游Stata检验 |
| **交互项检验** | LSZ×FT → 贷款规模扩大时FT对不良率的调节 | 面板已生成交互项基础列 | **可直接在Stata中构造** |
| **IV策略** | 所在省份金融科技公司数量 | 29套Bartik IV + LOO IV + DID | **项目远超论文** |
| **DID策略** | 银保监会2016年"十三五"规划 → 国有/股份制/上市为实验组 | DCEP + Fintech Sandbox (Callaway & Sant'Anna 2021) | **项目远超论文** |

> M-4的差距主要体现在**面板下游的Stata回归层面**，而非数据构建层。当前项目的面板数据已包含构建中介效应和交互项检验所需的全部基础变量。所需的改进是**在面板中预生成辅助变量**，降低Stata端操作复杂度。

## 2. 实质性改进项（宁缺毋滥）

### 改进 A: 金融科技指数三维子指数构建 (fintech_category三分法)

- **具体修改建议:** 在 `fintech_dict.json` 中为每个关键词追加 `dimension` 字段，取值为 `"strategy"`(战略理念)、`"technology"`(底层技术)、`"product"`(产品服务) 三分类。在 `21_tone_llms.py` 的 CoT 提示词中将 `fintech_category` 从二分(底层技术/应用场景)扩展为三分，新增"战略理念"选项。

- **论文依据:** 论文§2.4 明确按"战略理念""底层技术""产品服务"三个维度分别构建子指数，并在§3.2.1 表3 中分别回归（第2/6/10列为战略理念，第3/7/11列为底层技术，第4/8/12列为产品服务）。

- **预期边际贡献:** 
  - 增加**子维度异质性分析**的粒度：当前二分法将"战略理念"混入"应用场景"，可能模糊战略层面金融科技投入的独立效应
  - 论文发现产品服务维度FT系数不显著(表3列4/8/12)，而战略理念维度显著(列2/6/10)，三分法可复现该发现
  - 作为**稳健性检验**：三分法 vs 二分法的结果一致性

### 改进 B: 中介效应 Bank-Year 级通道变量预生成

- **具体修改建议:** 在 `43_panel_indicators_geography.py` 的 `compute_composite_indicators()` 中新增以下Bank-Year级变量：
  - `ft_intensity`: 金融科技强度 = `n_articles` / (该银行当年总新闻条数，需从12阶段全量数据回溯)
  - `ft_intensity_strategy` / `ft_intensity_tech` / `ft_intensity_product`: 三维子指数强度(依赖改进A)

- **论文依据:** 论文§3.1 公式(1): *Y_{i,t} = α₀ + γ₁FT_{i,t} + β₁X_{i,t} + μᵢ + ηₜ + ε_{i,t}*，其中 FT 定义为 FTWORD/NEWS，即**相对强度指标**(已控制银行层面新闻曝光度差异)。

- **预期边际贡献:**
  - 当前面板的 `n_articles` 和 `ln_news_coverage` 是**绝对量**指标，未控制银行"曝光"异质性
  - `ft_intensity` 直接对标论文的FT定义，使面板与论文具有**可比性**
  - 为Stata端中介效应检验提供现成的右手边变量

### 改进 C: "普而不惠"交互项预生成

- **具体修改建议:** 在面板导出时(45阶段)，为Stata回归预留交互项构建的说明和模板。具体而言，在Stata导出的变量标签中增加以下注释：
  - `LSZ × FT` 交互项（需在Stata端生成，因贷款规模来自Wind数据库）
  - 论文公式(2)的复现模板

- **论文依据:** 论文§3.2.3 表5 列6: 金融科技与贷款规模的交互项 LSZ×FT 对不良贷款率显著为负(t=-1.7889, p<0.1)，表明金融科技能抑制贷款规模扩大带来的风险。

- **预期边际贡献:**
  - 为"普而不惠"问题的检验提供方法论模板
  - 当项目获取银行财务数据后，可直接在Stata中复现

## 2. 阶段化执行指令 (SOP)

### 阶段一：机制重塑 / 数据清洗

#### 动作 1.1: 生成 `ft_intensity` 金融科技强度指标 [QW-1]

**交付物:** 在 `43_panel_indicators_geography.py` 的 `compute_composite_indicators()` 函数中新增 `ft_intensity` 列。

**执行步骤:**
1. 在 `45_panel_export_main.py` 的 `main()` 中，步骤 6b `compute_fintech_attention_index()` 执行后，读取 `12_fintech_news_full.parquet`（含全量银行新闻，包括非金融科技新闻）
2. 统计每家银行每年的**总新闻条数**（全量，不仅是金融科技新闻）
3. 计算 `ft_intensity = n_articles / total_bank_news`, 其中 `n_articles` 是金融科技新闻篇数，`total_bank_news` 是该银行当年全部新闻篇数
4. 特殊处理: `total_bank_news = 0` 时 `ft_intensity = NaN`（无新闻覆盖的银行）
5. 对标论文§2.4: *FT_{i,t} = FTWORD_{i,t} / NEWS_{i,t}*

**交付标准:**
- `ft_intensity` 列在面板中生成，取值区间 [0, 1]
- 描述性统计与论文表2的 FT 指标在量级上可比
- 日志输出 `ft_intensity` 的 mean/std/min/max

#### 动作 1.2: 三维分类标注 [CA-1, 可选]

**前置条件:** 需人工判断决策 — 是否将当前二分法扩展为三分法。

**交付物:** 
1. `fintech_dict.json` 中每个关键词追加 `"dimension"` 字段
2. LLM Prompt 中 `fintech_category` 扩展为三分类

**执行步骤:**
1. 在 `fintech_dict.json` 的每个关键词条目中增加 `"dimension"` 字段：
   - `"strategy"` — 战略理念类 (例: "数字化转型", "金融科技战略", "科技子公司")
   - `"technology"` — 底层技术类 (例: "区块链", "人工智能", "云计算")  
   - `"product"` — 产品服务类 (例: "手机银行", "智能客服", "在线贷款")
2. 修改 `config.yaml` 中的 LLM Prompt，将 `fintech_category` 从 `「底层技术」或「应用场景」` 改为 `「战略理念」「底层技术」或「产品服务」`

**交付标准:**
- 三分类覆盖率 ≥ 95%（每篇文章均有明确分类）
- 三分类在面板中生成 `n_articles_strategy`, `n_articles_tech`, `n_articles_product`
- 恒等式校验: `n_articles == n_articles_strategy + n_articles_tech + n_articles_product`
