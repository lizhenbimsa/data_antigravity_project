# 基于《Generative AI and Finance》的项目诊断与执行计划

=========================================
第一部分：基于参考论文的项目分析与诊断报告

1. 范式映射与盲区诊断：
参考论文《Generative AI and Finance》(Eisfeldt & Schubert, 2025)指出，大语言模型（LLMs）代表了金融文本研究方法的根本性技术冲击：LLMs能够基于上下文语境直接进行“零样本”分类，无需依赖传统的词语计数和特征工程。然而，论文在 3.7.2 节引述了 Wang et al. (2023) 的关键发现，即自回归大语言模型具有强烈的“位置偏见 (positional bias)”。如果让先输出定量/定性评分，然后再输出解释理由，模型仅仅是在对前面的盲目输出进行事后强行合理化（ex post reasoning），并不存在真实的因果推导。
当前 `news_process` 项目（阶段21）的 `config.yaml` 配置文件中设计了统一 LLM 推理 JSON 输出格式，然而其键值顺序是先判定结论（`is_bank_fintech_news`, `sentiment`）再解释理由（`verification_reason`, `sentiment_reason`）。这种结构完美踩中了论文警告的“位置偏见”盲区，极大限制了提示词框架中“思维链（CoT）”能力的真实发挥。

2. 实质性改进项（宁缺毋滥）：
- 改进 A：重构 LLM 推理输出机制，强制落实“先思考后结论”的 JSON 字段顺序
  -> 标明论文依据：论文 3.7.2 节 "Explanation and evaluation of LLM reasoning" 中明确提出的最佳实践指南——要求模型先生成解释，然后再输出分数，使逻辑与结论保持真正关联。
  -> 预期的边际贡献/解决的内生性问题：彻底纠正 LLM 的自回归因果错位问题，通过让输出生成强制经历实质性的逐步推导链，能大幅减少 LLM 在复杂或隐晦情感金融科技新闻分类上的幻觉（Hallucinations），提升三角验证机制的一致性与准确率。

3. 冗余剥离：
- 剔除传统的词频/词典情感分析模块（阶段22 `tone_words`）：
  论文 3.2 节强调，传统的分析方法（如依赖手工设定的正面/负面词库）无法捕捉文本中的上下文细微差别，并且LLM凭借上下文语境在进行复杂态度（如同行比较、含蓄否定）分析时远胜词频模型。既然当前项目已经成功建立了包含先进 LLM 与 BERT 模型的高阶体系，其极其繁重的词典匹配组件（以及庞大的否定词、程度词矩阵）已经不产生增量价值，仅仅是低效的架构包袱与“伪需求”，建议彻底从流水线中剔除。

=========================================
第二部分：项目重构与优化执行计划书

1. 优先级排布：
- 速赢项（Quick Wins）与核心攻坚项：核心动作在于修改提示词设定（零成本且瞬间生效）以及精简流水线（删除冗余节点）。这属于低实施成本但能大幅提升学术严谨度和代码运行效率的操作。

2. 阶段化执行指令 (SOP)：

阶段一（机制重塑/数据清洗）：
- 核心指令：直接编辑 `config.yaml` 中的 `<output_format>`。将其 JSON 字段排列顺序修改为：先强制进行逻辑思辨的过程字段，然后给出定性的结论字段。具体顺序为：
  1. `verification_reason`
  2. `is_bank_fintech_news`
  3. `confirmed_bank`
  4. `fintech_topic`
  5. `fintech_category`
  6. `verification_confidence`
  7. `sentiment_reason`
  8. `sentiment`
  9. `sentiment_confidence`
- 交付物：精准对应“先推导，后决断”要求的 `config.yaml` 配置文件更新。

阶段二（实证/模型重构与检验）：
- 核心指令：在 `config.yaml` 的 `sentiment_analysis.enabled_methods` 列表中删除 `tone_words`，进而全面废弃落后的词典情感分析方法；在并行任务调用脚本中，移除针对 `22_tone_words.py` 的执行和数据依赖。
- 稳健性检验标准：通过运行流水线自带的分类有效性评估（阶段33中 `classification_eval: true` 的代码），仅凭 `tone_llms` 与 `tone_berts`，验证其生成的指标是否能持平甚至更优，达到降低复杂度而保持信度的目标。

阶段三（结论重构）：
- 核心指令：在学术论文草稿或研究记录中，引述《Generative AI and Finance》(Eisfeldt & Schubert, 2025)的论点，声明本文通过“先释后判”的零样本思维链结构及端到端的深度语境推断，系统性地克服了LLMs的顺序依附偏见及传统词汇计数的失准劣势，由此证实该衡量体系的顶刊前沿级别稳健性。

3. 风险预案 (Plan B)：
- 致命卡点：强行禁用 `tone_words` 后，如果阶段 40 面板数据导出的环节（`45_panel_export_main.py`）或者伪造检验、各类评估代码中硬编码了对词汇集相关列名（如 `pos_words_count`, `tone_score_words`）的调用，会导致由于列名不存在而报 KeyError 异常中断。
- 替代预案：进入对应的聚合及评估脚本，添加宽容度极强的 `if 'tone_score_words' in df.columns:` 容错机制；若无法立刻定位所有的依赖关系位置，可安排一个轻量级的 Mock 脚本，在构建面板数据被读取前，向表中注入占位符为全 Null 的 `tone_words` 指标列群，从而绕过报错。
