# 基于《Decoding China's Industrial Policies》的项目评估与重构执行计划

## 第一部分：基于参考论文的项目分析与诊断报告

### 1. 范式映射与盲区诊断
**当前项目范式**：新闻处理流水线当前主要基于“二元边界与简单情感分类（正面/中性/负面）”以及“初级业务维度（底层技术/应用场景）”来衡量银行的金融科技发展。
**理论盲区**：根据文献《Decoding China's Industrial Policies》(Fang, Li, & Lu, 2025)，中国经济主体的行为（如产业资源配置）深刻受制于“自上而下（Top-Down）”的政策传导机制。地方政府或企业往往出台与上级高度一致的政策以展示政治忠诚或获取补贴（见论文 Fact 1b 与 1c）。当前项目在提取“银行金融科技新闻”时，未剥离“**被动政策迎合（Political Compliance）**”与“**主动实质创新（Autonomous Innovation）**”，极易将单纯响应监管号召或套取国家战略补贴的“伪创新”噪音计入真实发力水平，导致严重的内生性偏误。同时，将新闻简单划分为正负情感，掩盖了该金融科技动作背后真正采用的具体工具或手段。

### 2. 实质性改进项（宁缺毋滥）
- **改进 A：基于 LLM 解析“政策传导度/政治迎合性 (Policy Pass-through)”**
  - **具体建议**：在流水线大模型阶段（21的 Prompt_template）中，新增维度提取：判断新闻事件是否明确提及响应宏观战略、监管号召或五年规划行动。
  - **论文依据**：论文 Fact 1b 证明了典型的 Top-Down 传导效应，且在某些特定历史阶段有明显集聚。银行作为强牌照行业，政策传导极其显著。
  - **解决的内生性问题 (边际贡献)**：控制企业高管因晋升诉求而产生的“迎合性披露（Greenwashing/Tech-washing）”，在面板回归中引入“迎合性新闻占比”作为重要控制变量，深度提纯自变量中的“真实创新能力”。

- **改进 B：运用 LLM 深挖“金融科技施展工具分类 (Policy/Action Tools)”取代情感评分**
  - **具体建议**：借鉴论文对政策工具体系（Fiscal, Input, Supply Chain等）的结构化拆解法，由 LLM 将银行的金融科技事件细分为四类具体动作：1. 获取政府/监管扶持 (Government Support)；2. 自行研发与专利 (R&D Input)；3. 场景与供应链合作 (Supply Chain Cluster)；4. 同业竞争与防御 (Market Regulation)。
  - **论文依据**：论文 Section 3.5 分析指出，政策评估绝不仅是看“有无”或“积极性”，更要看它所调度的核心“Implementation Tools”。
  - **解决的内生性问题 (边际贡献)**：打破笼统的情感黑箱。情感“正面”是一致的，但“获批政府金融科技沙盒（外部支持）”和“自研大模型（内部研发）”对银行长期 ROA 的异质性影响截然不同。提供精准的异质性传导机制。

### 3. 冗余剥离
- **剥离项：阶段 22 和 23 的传统词典法与通用 BERT 情感模块**
  - **盲区诊断**：当前系统为了稳健性保留了词典法 (`tone_words`) 和微调 BERT (`tone_berts`)。然而，Fang et al. (2025) 第 2.4 节详细比对了 Keyword-based 方法与 LLMs 方法，以确凿数据证明词典法在涉及复杂长文本、语境反转和高维实体指代消解时，表现出极大噪音与词语污染。
  - **改进建议**：坚决剔除维护成本高且只输出低维情感分数的传统模块（Stage 22/23），将全部算力集中于现阶段已经部署的多模型“Hallucination-Robust LLMs”阵列，使得模型有充足 token 处理本报告提出的高维机制提取运算，实现高阶降本增效。

## 第二部分：项目重构与优化执行计划书

### 1. 优先级排布
- **速赢项（Quick Wins） - (修改成本低，即刻见效)**
  - 更改 `config.yaml`：注释或停用 `sentiment_analysis.enabled_methods` 中的 `tone_words` 和 `tone_berts` 选项。
  - 更新 `tone_llm_processing.prompt_template`，插入高级分类结构与输出要求。
- **核心攻坚项 - (涉及跨表级联更新)**
  - 基于新的 JSON 返回结构 (`policy_driven`, `action_tool`)，重构后续面板数据生成代码（如 `45_panel_export_main.py`），生成度量银行“合规迎合指数”和“工具异质性分布”的新量化指标。

### 2. 阶段化执行指令 (SOP)

- **阶段一（机制重塑与 Prompt 升维）：**
  - **核心动作**：修改 `config.yaml`。在原有阶段一（真伪）和阶段二（情感）之间，植入**被动政策响应 vs 主动商业创新**的判断规则；在结果 JSON 强约束中加入：`is_policy_echo (boolean)`，`fintech_action_tool (Enum: R&D, Cooperation, Government_Support, Others)`。
  - **交付标准**：LLM 的 Prompt 逻辑无缝集成这三个维度，并且确保 `verification_reason` 会阐述判别理由。

- **阶段二（实证/模型重构与检验 - 冗余处理）：**
  - **核心动作**：进入 `config.yaml`，直接将其中的 `threshold_sensitivity` 或关联过时工具的测试设为 `false`；从流水线依赖图中移除 `22_tone_words.py` 和 `23_tone_berts.py` 相关节点，彻底将情感与执行工具分类的主导权交给多模型融合的 LLMs。
  - **交付标准**：精简版流水线平稳通过阶段 36 的 Entity Masking 测试验证改写 Prompt 后的鲁棒性。

- **阶段三（结论重构与面板输出）：**
  - **核心动作**：修改阶段 40 面板数据集生成脚本。在汇总每家银行每年的 `fintech_news_count` 时，分拆新增两个核心子指标：`fintech_policy_echo_ratio` （政策响应色彩新闻的比例），以及按照 `action_tool` 的四大细分计数。
  - **交付标准**：最终产出的 `40_panel_yearly.parquet` 中包含以上无混淆控制变量，直接服务于核心实证发现。

### 3. 风险预案 (Plan B)
- **卡点预判：**单次 Prompt 任务过重（真伪+情感+政策响应+工具类别四个任务并行），可能导致部分 LLM 响应不收敛、格式破损或触发高频幻觉。
- **替代方案 (Plan B)：**引入参考论文中的**多阶段分解策略 (Decomposition)**。不再追求在一次大模型调用的 CoT 中解决所有问题。拆分为两个文件/模块：
  1. 第一个模块仅做金融科技文本真伪的严格二元分类（保留纯净语料）。
  2. 第二个模块仅针对极高可信度的 true 样本，进行机制深度拆解与政策迎合度计算。牺牲少量并发耗时，确保各小分项提取精确度攀升至顶刊免审级别。
