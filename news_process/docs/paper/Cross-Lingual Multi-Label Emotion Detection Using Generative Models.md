# 基于《Cross-Lingual Multi-Label Emotion Detection Using Generative Models》的项目评估与升级计划

=========================================
## 第一部分：基于参考论文的项目分析与诊断报告

### 1. 范式映射与盲区诊断
**范式提炼**：参考论文探讨了生成式大语言模型（LLMs）在跨语言文本多标签情感监测及强度预测任务中的效能极限。其核心论断在于两点：其一，由于中文金融评论和新闻的情感密集度极低（0-2个明显情感类别），要求模型进行一次性并发生成的**基本方法（Base Method）**在防断崖方面呈现出绝对碾压级的优势，远优于针对单个情感分别提问的对位法（Pairwise Method）；其二，LLM天然能够将零散的分类降阶，直接透视情感维度的定量规模并在高一致度上预测**情感量化强度（Emotion Intensity）**（基于皮尔逊检验相关的高可信度输出）。

**盲区诊断**：溯源当前 `news_process` 项目中的核心筛查算子 `21_tone_llms.py` （以及对应的 `config.yaml` Prompt框架），当前仅仅停留在原始的“强制性互斥单标签系统”（正面/中性/负面单选），存在极为严重的模型扭曲：金融科技赋能的真实商业演进，大多伴随“底层核心技术斩获破局（即结构性大正面）”伴生“由于沙盒监管试错带来的系统合规焦虑（结构性中高负面）”，强迫模型将其一维融合极易造成模型被迫妥协生成大量的“中性”结果导致一类误判（Type 1 Error），抹除了真实世界多极性信息。同时基于离散状态分类的输出阻断了后续截面连续变量的高频解释力。

### 2. 实质性改进项（宁缺毋滥）
> **维持原状：严禁进行冗长低效的多轮提问（Pairwise）改造**
> - **论文依据**：论文第5.3节实验严谨证实："In languages or datasets with a limited variety of emotional labels, such as Chinese... the base strategy demonstrates a distinct advantage."
> - **边际贡献/预期的保护**：本项目当前 `21_tone_llms.py` 实际上采用的便是单 Prompt（即隐性的 Base 法）。在此盲目切换至多代理/多分支询问将造成假阳性（大量弱相干信号被误吸纳）和API成本指数震荡爆炸。切记不要过度设计和“为改而改”。

> **改进 A：基于大样本量的一阶并发双模态（连续型）多标签强度预测框架**
> - **具体修改建议**：在统一 LLM 提示词中废弃 `[正面/中性/负面]` 单选题结构，全面转向离散正负情感并发强度判定。允许LLM并行评估并赋予该次事件对于目标主体的**利好（Positive）**与**冲击（Negative）**各独立输出 0 至 5 的独立量度，构建非互斥架构（类似于 Track B）。
> - **论文依据**：Track A 与 Track B 的结果指出指令微调后 LLM 对复杂短文本中的情感量度（Intensity）感知极为敏锐，无需分别通过小模型分拣并预测。
> - **预期的边际贡献**：提供精细化非互斥多维阵列。有效隔离并避免了诸如突破性创新伴随网络风险（如隐私泄露隐患）类信息互相冲销成为“中性噪音”。双连续量更可直接派生 “净干预强度 (Net Sentiment Intensity = Pos - Neg)” 以期满足下游 `45_panel_export_main.py` 的精细计量回归固定效应匹配。

### 3. 冗余剥离
原先于 `21_tone_llms.py` 下硬编码依赖过时分类学思路实现的 `majority_vote_sentiment()` （提取多数票众决逻辑）在多独立连续信号强度的度量中已然成为**伪需求模块**，并且其抹除次要情感权重的粗暴操作损害了三角共识。该模块应当予以直接剃除整顿。

## 第二部分：项目重构与优化执行计划书

### 1. 优先级排布
- **速赢项（Quick Wins）**：基于 `config.yaml` 中提示词模板（`prompt_template`）的改造，废除单级情感标签束缚，升级至并发强度的并行评估体制，收益快且不改变工作流上层建筑。
- **核心攻坚项**：`21_tone_llms.py` 的结果抽取重写与聚类聚合方法改造。摒弃众数决法则，向强度数值对齐和有效均值偏移法（Mean Intensity Validation）进阶。

### 2. 阶段化执行指令 (SOP)

**阶段一（机制重塑与底层规则修改）**：
- 载体与切入点：修改 `config.yaml`
- 动作指令：
  定位到 `<step2_sentiment>` 注入并发不互斥的约束指令法则："必须对事实本身单独评估利好（正面）触发的强度与负面或受挫风险（负面）的强度水平，二者独立量化，切勿生硬抵消计算"。
  重构 JSON `<output_format>` 的结构为：
  ```json
  "positive_intensity": "[整数0到5，0为无任何利好，5为颠覆性巨大利好]",
  "negative_intensity": "[整数0到5，0无任何负面，5为致命打击/严重下行风险]",
  "intensity_reason": "简述高频因子的评定根据"
  ```
- 交付标准：生成全新的提示词架构，不再强行输出类别。

**阶段二（模型重构与检验重置）**：
- 载体与切入点：修改 `21_tone_llms.py`
- 动作指令：
  重组 `_aggregate_track()` 数据捕捉及收敛法。丢弃 `majority_vote_sentiment` 后，采用在有效回答的大模型数据列中抽取三个强度数值执行算数平均以生成统一预测。将原输出的列标签迁移为 `llm_pos_intensity_{track}` 与 `llm_neg_intensity_{track}` 以及其标准差（衡量不确定性、共识涣散度以供稳健性自检）。
- 交付标准：Parquet 数据文件能稳健存储连续型的 `pos`、`neg`，并消除字符串处理错误。

**阶段三（检验标准重构）**：
- 载体与切入点：下游的人工校验评估脚本配置。
- 动作指令：针对原基于分类名义标签的 Cohen's Kappa 改写为应对不同法（大模型双轨与后续人工验证）情感强度的 **Pearson 相关系数（Pearson Correlation Coefficient）验证**（高度对标论文 Track B 指标范式）。

### 3. 风险预案 (Plan B)
- 致命卡点：由于所选异构大模型族群（如 GPT5 对比 Claude vs Gemini）内在自带对强度的理解“松紧尺度偏误”（如 Claude 若整体打分过于稳健导致极差小而不利于检验）。
- 实证替代方案法（Plan B）：执行组内强度校准（Relative Within-Group Standardization）。如果模型打分系统差异过大，则由后期 `41_panel_encode_aggregate.py` （或提取结束后的面板数据列存储时）将各不同模型原始分数单独提取，在面板级完成各模型的标准化 Z-score 规范处理或秩编码，之后再作等权合成 `Net Sentiment Index`，彻底屏蔽掉由于模型厂牌基础分布不同的外源性虚假震荡效应。
