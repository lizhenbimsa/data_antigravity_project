# 基于《Why Do Investors Like Short-leg Securities? Evidence from a Textual Analysis of Buy Recommendations》的项目分析与执行计划

=========================================
## 第一部分：基于参考论文的项目分析与诊断报告

### 1. 范式映射与盲区诊断
**范式映射与核心机制**：
参考论文（Chen et al., 2025）突破了传统文本特征（如简单的情感倾向/基调），提出基于行为金融学的“主观信念”文本拆解。论文将投资建议文本剖析为三大核心范式：预期通过防御性获得避风港效应的“感知安全（Perceived Safety）”、基于过去业绩外推和过度自信的“感知卓越（Perceived Supremacy）”，以及基于概率权重和高期望收益的“感知彩票特征/颠覆潜力（Perceived Lottery）”。
**盲区诊断**：
反观当前 `news_process` 项目的设计，主要依赖 `21_tone_llms.py`、`22_tone_words.py` 等实现“正面/负面/中性”的扁平化情感定性。这是一个明显的**研究视角落差**。
当前系统无法捕捉金融科技利好新闻背后的“认知驱动力”。由于金融科技本身既具有“防范风险、提高合规的防御属性（Safety）”，具有“提升市占率和垄断优势的护城河属性（Supremacy）”，同时也具有“颠覆现有业务模式但充满不确定性的博弈属性（Lottery）”，仅仅将其概括为“正面情感”，掩盖了异质性的信条传递路径。

### 2. 实质性改进项（宁缺毋滥）
>    - **改进 A：基于大模型的金融科技情感三维信念分解 (Safety / Supremacy / Lottery)**
>      - **写明具体修改建议**：在 LLM 的 Prompt 模板中增加指令，针对情感判定为“正面”的金融科技新闻，进一步进行归因分类，提取主导逻辑是防御稳健（Safety）、行业领先（Supremacy）还是颠覆潜力（Lottery）。若无明显特征则归为 Inconclusive。
>      - **标明论文依据**：论文 Section 2.1 （Three frameworks）对这三维框架的严密理论界定，以及 Section 3.1 和 Table 2 中提出的文本特征切分与分类统计逻辑。
>      - **预期的边际贡献/解决的内生性问题**：彻底改变现有一维的“情感(Sentiment)驱动效应”，探索金融科技创新的微观影响异质性。解决诸如“不同金融科技新闻虽然均反映利好，但因为感知差异，对银行存款稳定性或股价波动的最终影响完全相反”的遗漏变量内生性痛点。

>    - **改进 B：构建细粒度、多层次的 Bank-Year 认知异质性面板数据**
>      - **写明具体修改建议**：在面板聚合阶段生成 `Safety_index`, `Supremacy_index`, `Lottery_index` 三个独立新指标，取代或辅助原有的总情感指标。
>      - **标明论文依据**：同论文对三种叙事占比的定量测度逻辑，验证不同异常特质下的支配性解释因素（对应原文 Section 3.2 Evidence by economic categories）。
>      - **预期的边际贡献/解决的内生性问题**：使得后续的 DID 和工具变量分析具备探讨“机制异质性”的接口，进一步提高文章向顶级财务/金融期刊投稿的理论深度。

### 3. 冗余剥离
**伪需求模块**：当前流水线中基于基础词典的情感分析 `22_tone_words.py`。
由于本文拟引入深层“主观信念范式”的三维拆解，传统简单正负面词典法的维度过于扁平，已不具备实证上的核心竞争力。原文中也指出字典法具有局限性并通过 BERT 进行了验证（Section 4.4）。鉴于当前项目已接入完善的 LLM 流程，建议直接**剔除**使用静态正负面词典的步骤，集中算力资源和数据流程在基于泛化大模型多维分类的实现上。

## 第二部分：项目重构与优化执行计划书

### 1. 优先级排布
- **速赢项（Quick Wins）**：
  直接修改 `config.yaml` 中的 `prompt_template`，调整 `<output_format>` 的 JSON 输出结构，加入 `cognitive_dimension` 字段，实现大模型输出时自动对“正面情感”赋予具体范式（Safety/Supremacy/Lottery/Inconclusive）。
- **核心攻坚项**：
  在后段的聚合模块（`41_panel_encode_aggregate.py` 及 `45_panel_export_main.py`）中计算安全/卓越/彩票类型词频占比并加权，构建多维面板数据集。

### 2. 阶段化执行指令 (SOP)

**阶段一（机制重塑与指标重构）**：
- 动作指令：编辑 `config/config.yaml`。在 `tone_llm_processing.prompt_template` 内添加关于金融科技文本的三维认知框架定义规则。
  - Safety：与抗风险、稳定性、防御性相关的科技应用描述。
  - Supremacy：与行业领导力、市场份额扩张、强劲增长预期的描述。
  - Lottery：与爆发式增长、未充分验证的深度颠覆、高风险高回报相关的描述。
- 交付物标准：无报错且能正确引流输出上述新增 JSON 字段的 updated `config.yaml` 配置文件。

**阶段二（实证面板聚合模型升级）**：
- 动作指令：在 `41_panel_encode_aggregate.py` 中，接驳 LLM 新增字段解析；在执行 `groupby` 年度聚合及计算媒体权威度加权逻辑时，增设计算 `fraction_safety`, `fraction_supremacy`, `fraction_lottery` 三个特征指标的衍生变量序列。
- 稳健性检验标准：采用与论文一致的相对差分算法（如式 (1)中度量偏离度的 Delta 计算）以及归一化逻辑生成最终认知度得分，并利用后续伪造检验模块 `51_falsification_test.py` 检测各序列在非关联年度的安慰剂有效性。

**阶段三（回归与结论重构）**：
- 动作指令：移除流水线中专门依赖 `22_tone_words.py` 词典打分的分支。在核心的面板统计导出结果文件结构内彻底切换为：核心自变量替换为基于多维度认知的 Fintech 指数矩阵。

### 3. 风险预案 (Plan B)
- **风险预判**：大模型对部分通稿或宏观背景新闻往往无法给出安全、卓越或彩票的有效划分，强行指定可能导致模型幻觉（Hallucination）。这种不可归类（Inconclusive）的样本过多可能导致指标分布过于稀疏。
- **替代方案 (Plan B)**：
  - 遵循论文中允许“Inconclusive”（原文占比 20%-30%）的统计事实。在 Prompt 中明确增加“若信息模糊且不能归属三大信念，强制返回 `Inconclusive`的出口项”。
  - 当稀疏性过高时（如非零率低于10%），对指标形态进行转换，将连续型的词频占比转化为二值型虚拟变量（Dummy Variable：当年是否有超常的异质性信念新闻），确保后续回归的收敛和方差稳定性。
