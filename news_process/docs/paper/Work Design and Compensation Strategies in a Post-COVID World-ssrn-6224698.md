# 执行计划书：基于《Work Design and Compensation Strategies in a Post-COVID World》的项目重构报告

=========================================
## 第一部分：基于参考论文的项目分析与诊断报告

### 1. 范式映射与盲区诊断
**论文核心机制：** 参考论文突破了传统的单维度文本分析（如简单情感或主题），运用大语言模型（LLM, GPT-4o-mini）通过角色设定与少样本提示（few-shot prompting），在非结构化文本（招聘信息）中并发提取了**六个复杂维度的组织特征（工作设计维度：技能多样性、任务完整性、任务重要性、自主性、反馈、远程工作可行性）**。更关键的是，论文构建了“外生宏观冲击（连续测度的地区COVID严重程度） -> 文本显现的微观组织特征变化 -> 经济后果（薪酬调整）”的清晰传导链条，并引入“职业非例行性”作为文本内生的异质性调节变量。

**当前项目盲区：**
整个 `news_process` 项目目前过度强调“情感/基调（Tone）”这一单一维度的计算（如 `21_tone_llms.py`、`22_tone_words.py`、`23_tone_berts.py` 并排运行）。当前项目不仅停留在判断一维的“正负面”，而且在实证策略上（`44_panel_iv_did.py`）缺乏与具体而深刻的外生结构性冲击带来的多维度异质性互动。我们的盲点在于**将极其丰富的非结构化新闻文本扁平化为单纯的“媒体情绪指标”**，从而错失了挖掘新闻中所揭示的企业深层结构、组织机制变革和应对不确定性战略的多维价值。

### 2. 实质性改进项（宁缺毋滥）

> - **改进 A：由“单维情感字典”向“多维底层特征提取”跃迁**
>   - [具体建议]：摒弃让 LLM 只做“正面/负面”打分，重构 `21_tone_llms.py` 的 prompt，应用论文中展示的“角色扮演 + 提供理论定义 + 少样本示例”的技术，让模型在新闻文本中同步提取企业的“应对外部冲击敏捷度”、“远程办公/数字化适应度”、“内部控制机制变化”等多项结构维度，采用1-5的李克特量表输出。
>   - [论文依据]：论文 [LLM-based Measures] 章节，利用 GPT-4o-mini 同步产生 5 点李克特量表得分与 WFH 0/1 判定。
>   - [预期边际贡献]：极大提升项目研究的上限，解决仅靠媒体情感解释力弱的内生性问题。将文本的作用从“外部舆论噪音”深化为“透视内部治理与工作设计的窗口”。

> - **改进 B：引入连续处理强度的 DID 机制检验外生冲击**
>   - [具体建议]：在 `44_panel_iv_did.py` 中参考论文构建连续冲击变量（Continuous DID Treatment，例如地级市层面的公共卫生冲击暴露度），以测试新闻中反映的企业组织特征如何随外生压力发生变异。
>   - [论文依据]：论文 [Analytical Strategy] 中利用公式 (1) 将城市感染率作为连续 DID 处理变量 `COVID Case_nt`。
>   - [预期解决的问题]：彻底解决单纯时间截面回归的反向因果问题，为金融文本驱动经济结果的逻辑链条加上严密的“准自然实验”锚点。

### 3. 冗余剥离
当前项目中围绕词典匹配的模块（如 `22_tone_words.py` ）以及普通的 BERT 微调探索（`23_tone_berts.py`），在面对需要高阶语义和理论映射的“多维复杂测量”时，存在严重的“形式主义跑分”嫌疑。
**判决：明确指出偏离主线的冗余模块。建议直接剔除 `22_tone_words.py` 和 `23_tone_berts.py` 及其依附的相关测试组件，将全部微弱算力聚焦于打磨前沿 LLM 的高级 Prompt 与校验模块（如 `32_news_llms_human.py` 和 `33_news_llms_evaluation.py`）。**

## 第二部分：项目重构与优化执行计划书

### 1. 优先级排布
- **速赢项 (Quick Wins)：** 清理现存的词典方法与 BERT 残留代码，精简特征流水线；重构现存的 `21_tone_llms.py` 的 Prompt 结构，加入角色扮演设定与 Few-Shot 标准范例。
- **核心攻坚项：** 在 `44_panel_iv_did.py` 中清洗并锚定连续空间地理的外部冲击变量（如疫情强度），建立有向的连续 DID 模型验证实证逻辑。

### 2. 阶段化执行指令 (SOP)

**阶段一（机制重塑与数据清洗）：**
- 核心动作指令：剔除并清理低效文件（`22_tone_words.py`, `23_tone_berts.py`）。将原 `21_tone_llms.py` 升级为支持多维度李克特量表打分的LLM流水线程序。
- 交付物标准：输出的 Prompt 必须强制要求按照预定义的 Json 或结构化列表输出多维提取结果（如 `[id, agility_score, remote_score, significance_score, sentiment_score]`），不再容忍冗杂的自然语言输出。

**阶段二（实证模型重构与检验）：**
- 核心动作指令：重构 `44_panel_iv_did.py`，植入连续变量 DID (`Shock_ct * Post_t`) 及其交互项。同时引入类比于论文中“职业非例行性”的文本内生异质性调节变量（如技术/研发密集度）。
- 稳健性检验标准：遵循论文，必须通过 bootstrapped 置信区间的因果中介效应机制进行 Monte Carlo 条件间接效应排查，拒绝简单 OLS。

**阶段三（结论重构）：**
- 核心动作指令：更新分析输出流程 `45_panel_export_main.py` 以兼容新的多维修补结构。生成严密锁定于“外部冲击如何经由企业内在组织设计最终映射并由媒体捕捉发声”的连贯故事线报告。

### 3. 风险预案 (Plan B)
- 致命卡点预判：新闻数据关于底层工作设计和微观机制的描写过于宏观和稀疏，可能导致大模型进行五点李克特评分时缺乏信息依据、趋同于基础分（产生严重的零通货涨缩效应）。
- 替代方案：不要强行套用复杂的五级细化量表，而是退回到更具颗粒度的 Binary 探测，即基于新闻文本监测是否提及特定的“组织反应标记点（Markers）”（WFH政策响应 0/1、灵活排班 0/1、业务收缩防守 0/1），通过频数加总缓解个体稀疏度造成的量化不稳定现象。
