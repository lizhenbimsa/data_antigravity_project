# 基于参考论文的项目分析与诊断报告

=========================================
第一部分：基于参考论文的项目分析与诊断报告

1. 范式映射与盲区诊断： 
**论文核心机制提炼**：本文是对 ChatGPT 及大型预训练语言模型（LLMs）在会计和金融领域应用范围的系统性综述。文章揭示了 LLMs 当前的核心优势（文本分类、情感分析、金融语境信息抽取与前瞻性分析、基于 Embedding 的语义表征提取）以及在企业金融、资产定价领域应用。同时，文中高度强调了对 LLM 的提示词敏感性、幻觉及内在认知偏差的稳健性控制。
**当前项目的盲区诊断**：通过检视 `news_process` 的 `config.yaml` 配置文件，当前项目在稳健性控制（如：Entity Masking 测试、Prompt 敏感度测试——阶段31-39）已经达到了论文里倡导的学术前沿和最高标准。然而，当前在研究视角的信息提炼程度上存在显著的真实落差：阶段 21（LLM 精筛）仍停留在“该新闻是否为该银行相关金融科技新闻”及“正面/中性/负面（传统单维情绪）”的基础输出维度，未能利用论文中反复提及的对“特定风险（Risk Exposure）”、“前瞻性战略陈述（Forward-looking Statements）”以及“长文本深度逻辑总结（Summarization）”的提取潜能。这导致特征池维度单一，对核心实证故事的边际贡献存在天花板。

2. 实质性改进项（宁缺毋滥）： 
- 改进 A： [将 LLM 语义输出维度从“单向情感极性”拓展为包含“特定风险暴露”与“技术前瞻意图”的多维评估] -> [标明论文依据：Section 4.3.6 与 Section 4.2.3，Kim et al. (2023b) 表明由于 LLMs 有能力处理长文本及推理，提取公司在政治、气候等特定主题的风险暴露以及未来长期战略预期上的表现显著优于单薄的情绪分析，对波动率与投资有着极高预测价值。] -> [阐述预期的边际贡献/解决的内生性问题：改变简单的乐观/悲观情绪二分法带来的信息损耗，新增的风险暴露与前瞻意图能极大丰富最终面板数据控制特征。控制管理层意图有助于消减遗漏变量误差（Omitted Variable Bias）。]

- 改进 B： [引入基于 LLM/Transformer 的 Contextual Word Embeddings 进行深度语义对比，提升去重与“信息新颖度”度量] -> [标明论文依据：Section 4.3.1 Word embeddings ；Breitung and Müller (2023) 提出生成的语境词向量，在识别文档的相互关系及信息重复上大幅超越字面匹配方法。] -> [阐述预期的边际贡献/解决的内生性问题：目前阶段 00 严重依赖基于字符的 n-gram 与 MinHash 技术（Jaccard系数）计算去重，该方法对于“洗稿”公关长文极其无力。引入 Embedding 降维相似度距离测算，能精准剔除深度意译重复稿，有效消除新闻数据中的冗余信息冲击造成的系统性衡量偏误（Measurement Error），提取真正的新闻创新（Novelty）异质性。]

3. 冗余剥离：
**伪需求模块——过时复杂的重度人工词典设定**：目前的配置 `config.yaml` 的阶段 22（`tone_words`）充斥着海量的复杂规则，比如转折词乘数加权（`adversative_boost: 1.5`）、针对否定词范围的移动滑窗（`negation_window`）、包含几十个精细分级乘以不同权重分值的程度副词修饰系统。正如论文 4.3 节强调，LLMs 作为注意力机制主导的深度模型，其在结合转折、程度、金融短语等复杂语境的处理上，已形成降维打击优势。当前已启用多模型集成投票机制的先进框架下，过度繁杂、拍脑袋设定的规则词典不仅是低价值冗余的无用功，其权重强设定所内含的人工主观性甚至会给数据造成噪声。建议将基于规则的情感加权完全剥离脱落，重归极简的原始正/反词频控制变量记录级即可。

第二部分：项目重构与优化执行计划书

1. 优先级排布： 
- 核心攻坚项（优先实施且高价值）：重构 21_tone_llms 阶段的 Prompt CoT 指令架构，融合“风险类型标签”与“前瞻性特征”抽取（高收益，低开发成本）。
- 核心攻坚项（逐步实施挑战强）：升级 00_preprocessing 阶段相似度去重复算法，利用大模型 Embedding 获取语义并聚类新颖度计算。
- 速赢项（Quick Wins）：精简 22_words_tone 面向人共设定的冗余规则（即刻收益，实施零成本，规避评审攻击）。

2. 阶段化执行指令 (SOP)：

- 阶段一（机制重塑/数据清洗）：
  核心动作指令：进入 `config.yaml` 下 `tone_words` 模块配置，抹除或强制失效 `adversative_boost` 及 `degree_words` 的复杂组合加权规则计算逻辑。引入本地轻量句向量抽取（如 Sentence-Transformer）或云端向量映射 API ，对处理的新闻数据批量提取特征词嵌入（Embeddings）。
  明确的交付物标准：简化后的 `config.yaml`；阶段归档的 `00_preprocessing.parquet` 中补充新闻全文的 `embedding_vector` 列与 `novelty_score`（新颖度分值）列。

- 阶段二（实证/模型重构与检验）：
  核心动作指令：进入 21 阶段，向三大底层模型传递更新的 JSON 输出模板。除了 `is_bank_fintech_news` 和 `sentiment` 外，必须指明模型返回额外两键 `forward_looking`（布尔极性，是否包含重大技术部署计划）与 `risk_class`（返回业务风险/合规处罚风险/无风险等的 enum 值）。
  稳健性检验标准：将修改后的 JSON schema 一并合并加入到 36 阶段（实体遮蔽一致率检验机制）针对新增指标一致性确保 kappa > 0.8。新的变量汇总至阶段 40（40_panel_yearly.parquet）产出基于银行-年的暴露特征。

- 阶段三（结论重构）： 
  核心动作指令：依托包含新变量维度的 Bank-Year 数据，在 Stata 或 Python 环境中搭建引入这上述新衍生变量的调节效应或多期 DID。重写实证章节，证明大模型发掘出的隐藏细粒度特征(风险标签、语义新颖度)与公司异质性对冲之间的显著因果关联。

3. 风险预案 (Plan B)： 
致命卡点预判：阶段一在执行百千万级文章互相比较提取 Cosine Similarity 时，可能遭遇内存上限 $O(n^2)$ 耗尽及 LLM 接口的高昂调用费用断供问题。
替代方案：退回方案：抛弃所有在线商业 API 用于清洗或相似距离计算，改为使用高度压缩的中文本地模型（如 `text2vec-base-chinese` 等轻量化方案）获取 Embedding；将两两新闻距离计算重构为 Faiss (相似度快速检索层) 或截断至局部的“单日同业新闻圈”相似查找规避全局爆炸计算。
