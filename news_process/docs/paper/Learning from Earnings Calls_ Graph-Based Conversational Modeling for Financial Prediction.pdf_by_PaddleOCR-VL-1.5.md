# 基于《Learning from Earnings Calls》的项目审计与执行计划

## 第一部分：基于参考论文的项目分析与诊断报告

### 1. 范式映射与盲区诊断
论文《Learning from Earnings Calls: Graph-Based Conversational Modeling for Financial Prediction》的核心理论贡献，在于突破了传统金融文本挖掘中常见的“线性序列”与“词袋（Bag-of-Words）”范式。它将复杂的长文本（财报电话会议摘要）创新性地重构为**对话逻辑图谱（Conversational Graph）**。研究证明，文本中真正具有预测效力的信号往往稀疏分布，且隐藏在话题的“新颖性（新增话题数）”与各议题之间的“交叉引用（Cross-referencing）”拓扑结构中，而绝不仅仅是情感词的加总。

**对当前 `news_process` 项目的诊断：**
当前项目严重依赖线性信息提取：只通过字典匹配（`22_tone_words.py`）、BERT线性滑动窗口（`23_tone_berts.py`）以及浅层LLM情感分类（`21_tone_llms.py`）抓取相对孤立的情感倾向和关键词共现频次。它**完全忽略了文本内部复杂多维的网状逻辑结构**。对于深度的长篇金融科技新闻而言，当前框架无法捕捉到银行“技术攻坚”、“合规风险控制”、“业务场景落地”等多个实体话题间的“交叉引用”。这种结构性盲区，容易把“只具噱头的技术堆砌（毫无业务交叉）”与“深度的结构转型（技术深度嵌入各业务节点）”混为一谈。

### 2. 实质性改进项（宁缺毋滥）
>    - **改进 A：由线性度量向结构化度量转型——构建“新闻内部话题拓扑（News Topical Graph）”指数**
>      - **论文依据**：论文明确提出 "explicitly model what is discussed and how it is discussed (cross-referencing or newly introduced topics)"，并证明图结构指标对于预测风险至关重要。
>      - **预期边际贡献 / 解决的内生性问题**：通过引入单篇新闻内部的“话题交叉耦合密度（Topical Graph Density）”和核心技术项的“交叉引用指数（Cross-reference Index）”，可以从统计上直接剥离出那些为了“数字化洗绿/公关炒作”而凑字数的新闻。真正有长期价值的报道，其金融科技要素必然高频地与“风险控制”、“信贷投放”、“客户增长”等节点形成图拓扑上的紧密连接（Edges）。这极大提升了数字化转型变量的测度效度（Validity）。

>    - **改进 B：识别“话题新颖度（Topic Novelty/Emergence）”**
>      - **论文依据**：论文实验显示模型 "tends to associate transcripts with a higher number of new topics... with lower predicted financial risks"。新话题常常预示着实质性突破。
>      - **预期边际贡献 / 解决的内生性问题**：针对当前只判定“是否涉及金融科技（是/否）”的粗糙维度，补充“该技术落地行动是对过往战略的重复赘述（Redundant），还是具备市场首发性/开拓性（Novel/First-mover）”的维度，增强解释变量的异质性信息粒度。

### 3. 冗余剥离
明确剔除模块三中**基于传统预训练模型的情感打分管道（`23_tone_berts.py` 及相关 `tone_berts` 模块）**。单纯的BERT情感分类在处理千字以上的长新闻时，会不可避免地导致信号稀释稀释（Dilution）；且其注意力机制的上限也无法替代显式的图结构拓扑表征。在已经采用统一大模型思维链（`21_tone_llms`）的前提下，此类粗粒度的基线模型属于“伪需求”，徒增项目算力成本与工程复杂度，建议直接剥离，将开发时间和算力转移至图谱特征构建。

## 第二部分：项目重构与优化执行计划书

### 1. 优先级排布
- **速赢项（Quick Wins）**：
  - 更新现有的 LLM Prompt，在解析情感和真伪的同时，顺带结构化提取并统计文中的“核心话题节点”及其“边关联（相互提及的情况）”。成本极低，收益立竿见影。
  - 直接在工程层面删除/冻结老旧低效的 `23_tone_berts.py` 模块。
- **核心攻坚项**：
  - 新增图拓扑计算逻辑：基于提取出的话题共现网络，通过算法严谨地计算新闻内话题的“交叉引用中心度”，建立更高级的面板异质性控制变量。

### 2. 阶段化执行指令 (SOP)

**阶段一（机制重塑与特征升维）：**
- **核心动作指令**：直接修改 `config.yaml` 中的 `prompt_template`。将原本单纯 JSON 输出结构扩充。要求 LLM 充当“实体话题提取器”，针对每篇新闻输出：(1) `topics` (涉及的具体业务/技术模块列表)，(2) `cross_references` (技术如何关联到具体业务场景的描述)，(3) `topic_novelty_score` (该动作是行业新面世还是老生常谈，打分1-5)。
- **交付物标准**：更新后的 `21_tone_llms.parquet`，其中包含了 `topics_count`, `cross_reference_edges`, `novelty_score` 等结构化字段。

**阶段二（实证模型架构演进）：**
- **核心动作指令**：新增特征工程脚本（如 `24_topic_graph_features.py`）。读取上述提取出的节点和边数据，借助 NetworkX 快速计算该文档的“拓扑耦合度（Topical Coupling Density）”。
- **稳健性检验标准**：在计量模型（Stata面板）上，对金融科技注意力指数（Fintech Attention Index）执行交互项回归：验证 `Fintech_Index × Topical_Coupling_Density` 是否吸收了大部分对于银行未来绩效提升（ROA/不良率下降）的正向解释力度。

**阶段三（结论重构）：**
- **核心动作指令**：在论文正文及汇报中重新定调。即：“不光要看银行喊了多少次‘金融科技’的口号（Count），更要看这篇新闻在深层话语逻辑中，有多少个实质性业务触角（Cross-references）与新技术形成了紧密联结，这才是区别实质落地与象征性披露的试金石。”

### 3. 风险预案 (Plan B)
- **风险预判**：要求 LLM 严格提取大量新闻的 Graph 节点和互引用节点，由于长尾长文本可能引发大模型的幻觉（Hallucinated Edges）或者 Token Output OOM（输出极大数组导致截断）。
- **Plan B (替代方案)**：如果 LLM 输出频繁失败，切回确定性的 NLP 方案。在文本中利用基础分词和词典，只要在**两个相邻的句子窗口（如 3个句子的滑窗）**内，同时命中“底层技术词”（如：区块链）与“金融业务词”（如：供应链金融/风控），且不包含强转折/否定词，就计算为 `+1` 个 Cross-reference Edge，用最轻量的规则统计平替昂贵的生成式图谱信息抽取，确保大规模语料在普通算力下的实证可用性。
