# 基于参考论文的金融研究流水线评估与执行计划

**参考论文:** *Surviving the Fintech Disruption* (Jiang et al.)

## 第一部分：基于参考论文的项目分析与诊断报告

**1. 范式映射与盲区诊断：**
参考论文利用基于自然语言处理的词分布与相似度（Word Embedding）技术分析金融科技专利和O*NET职业任务的文本重叠，构建“职业层面的金融科技暴露度”（Occupational Exposure to Fintech），并指出企业必须通过“人才技能升级（Finance + Tech复合型）”、“内部人力资本重构”及“技术创新转型”等实质性举措来抵御金融科技冲击，进而实现生产率和市值的增长。
当前项目（`news_process`）的盲区在于：系统严格依赖外部分布（即各家银行的新闻发声频率和基本情感倾向）来度量金融科技关注程度。这就将所有的新闻不论其落地程度如何，全部赋予相似权重，未能有效区分表层的“产品宣发口号（Tech-washing）”与牵涉企业底层实质性调整（复合人才涌入、科技部门设立与组织转型）的深度战略执行，导致对因变量（真实创新意愿）的混杂模糊。

**2. 实质性改进项（宁缺毋滥）：**
- **改进 A：在统一LLM语义精筛中引入“组织机制与人才升级”识别维度。**
  -> **[标明论文依据]**：论文第4节至第5节强调，金融科技的颠覆不仅是业务自动化，核心在于对兼具金融与科技技能（“Finance + Tech”）复合型人才产生的强刺激。能够成功抵御冲击的企业，必然展现出技术团队的扩张与内部组织的重组。
  -> **[预期的边际贡献/解决的内生性问题]**：针对新闻的语义分析中，必须剥离虚假炒作。通过探测新闻中是否包含“金融科技专门研究机构设立”、“科技跨学科人才招揽”、“底层业务架构与网点重构”的实质性举措，构建出更加硬核有效的“转型实质深度代理变量（Proxy）”，解决简单的频度计算带来的“技术词汇洗白效应”，分离出具有坚实基础的适应性策略。

- **改进 B：从粗略的类型分类升维至七大专属前沿细分技术赛道映射。**
  -> **[标明论文依据]**：论文第2.1.1节利用机器学习算法准确将金融科技专利细分为网络安全（Cybersecurity）、移动支付（Mobile Transactions）、数据分析（Data Analytics）、区块链（Blockchain）、P2P（Peer-to-Peer）、智能投顾（Robo-Advising）及物联网（IoT）七大特定类目，并证实各个领域所造成的影响效力具有显著的周期性差异。
  -> **[预期的边际贡献/解决的内生性问题]**：由于项目中现行的LLM只将金融科技简单分为“应用场景”或“底层技术”，分类缺乏细粒度的理论支撑。通过全面引入这七大权威赛道，极大增强所构建面板数据词频或声量的合法（Validity）验证背书，并可为实证部分建立“多维度技术时序冲击差分”等高阶横截面异质性检验提供权威因子结构。

**3. 冗余剥离：**
- **结论：维持核心基准原状，拒绝形式主义的多源倒灌。**
尽管论文采用了职位广告文本(Burning Glass)、核心专利数据(USPTO) 等构建技术冲击指数，但研究数据基座的属性不同。若为了单纯去贴合参考论文的范式，盲目扩大并爬取出相悖的多源数据集，不仅造成研究主体的逻辑断裂，也是纯粹的“为改而改”。本项研究应直接“**维持原状**”——保留专一、高质的中国财经新闻流语料壁垒，不掺杂外部冗余表格。

## 第二部分：项目重构与优化执行计划书

**1. 优先级排布：**
- **速赢项（Quick Wins，实施成本极低，预期学术收益高）**：立即调整配置文件 `config.yaml` 中向 LLM 并发核心节点注入的 Prompt Schema 结构。在原本仅筛定真伪与倾向判断同时，增加并行输出“七类赛道分类参数”与“实质人才组织升级标记”，在算力零增量的情况下一次出库完成。
- **核心攻坚项**：对后续的年度聚合面板构建逻辑模块进行重组升级设计（`45_panel_export_main.py`），对高并发的打标签结果进行学术级指数编纂与校验聚合算法设计，以应对回归模块的要求。

**2. 阶段化执行指令 (SOP)：**

- **阶段一（机制重塑/数据清洗）：**
  - **核心动作指令**：
    1. 修改项目配置文件 `config.yaml` 内 `tone_llm_processing.prompt_template`。
    2. 将原有的 `fintech_category` "「底层技术」或「应用场景」"，彻底扩充迭代为参照 Jiang et al. 范式的七分类强制映射：`网络安全、移动支付、数据分析、区块链、P2P、智能投顾、物联网`。
    3. Prompt 模板指令输出 JSON 中新增强制校验字段 `substantive_organizational_shift`（取 Boolean 或短文本；用于判断该新闻是否披露了任何实质性的跨界复合人才引进、独立研发机构落地、架构系统与网点硬核重构行动），直接排斥纯泛化宣讲。
  - **明确的交付物标准**：跑通 LLM 映射管道，并保存能够输出具有前述两项学术硬核新增参量的完整 `config.yaml` 配置补丁。

- **阶段二（实证/模型重构与检验）：**
  - **核心动作指令**：升级项目模块中生成 Bank-Year 面板数据集合的衍生构造阶段逻辑定义环节。
  - **稳健性检验标准**：增加构建“金融领域赛道赫芬达尔指数（HHI，衡量多元技术融合纵深）”和生成代表真正抵御实力的“实质重组报道声量比（Substantive Shift Action Ratio）”变量序列。

- **阶段三（结论重构）：**
  - **核心动作指令**：在实证计量框架模型设计部分生成结论论据推演模板——全面引入交互项检验框架，比如 `Log(Fintech News) × Substantive_Shift_Ratio`，以实证推断出“仅仅是泛滥的新闻宣传是难以扭转冲击逆势的，唯有实质化伴随内部人力与组织底层体系重购动作的新闻溢出，才能成功抵御重器冲击并为个体获得确切绩效扩张红利”。

**3. 风险预案 (Plan B)：**
- **致命卡点预判**：银行外部新闻披露和上市企业的定期公开通告文本环境不同于详细的招聘需求库（Burning Glass），对外新闻较少细化到基层人才培养与复合技能岗位设置，有可能造成提取的 `substantive_organizational_shift` 这个维度的数据极度稀疏（绝大多数都是 false）。
- **可执行替代方案**：若发现因变量过于稀疏模型遭遇奇异值分解降维打击或不收敛，迅速触发启用同等实质效力的理论降维替代指标 ——**强排他性战略研发同盟（Strategic Tech Alliance & Co-innovation）**。逻辑依据：现代银行面对冲击且自有人才池枯竭时，其最常态化应对模式便是在其通稿中大规模展示与外源强力科技企业（如 BAT、华为及清北交叉实验室）达成战略绑定。LLM 可极为精准判别且语料丰度极高。这一代理变量同样完美呼应并契合了该论文主旨中宣扬的利用 “Tech + Finance” 跨界技能互补来吸收抵御技术颠覆的机制原理。
