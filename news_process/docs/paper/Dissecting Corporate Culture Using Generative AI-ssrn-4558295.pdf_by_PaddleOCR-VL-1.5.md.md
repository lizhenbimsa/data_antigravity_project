# 基于《Dissecting Corporate Culture Using Generative AI》的项目诊断与重构执行计划

## 第一部分：基于参考论文的项目分析与诊断报告

### 1. 范式映射与盲区诊断
**论文核心机制**：该论文突破了以往使用传统词典法或仅进行情感极性分类的局限，创新性地引入了 **生成式AI（带有思维链与RAG检索增强）进行因果关系抽取（Cause-Effect Extraction）**。论文通过提取“前因（谁/什么事件推动） -> 现象（企业文化类型） -> 后果（业务影响）”的结构化三元组，并叠加情感分析，深入挖掘了文本的因果逻辑，发现具有深刻逻辑推理（给出因果分析）的研究者或文本对金融市场有着更为显著的溢价预测和解释力。

**当前项目落差**：当前 `news_process` 项目（针对银行金融科技新闻）的 LLM 提示词模板高度集中于 **“新闻真伪鉴定”** 和 **“三维静态情感倾向判定（正面/中性/负面）”**。当前项目忽略了新闻文本中关键的内部逻辑链条，即**未抽取出“银行发展金融科技技术的动因（如政策监管、同行扩张、创新驱动等）”及其“预期或已产生的业务后果（如降本增效、获客提升等）”**。实证实操上，这使得后续的面板数据回归停留在粗颗粒度的“正面情绪冲击”层面，缺乏对技术引入异质性驱动及其后果的机制解释。

### 2. 实质性改进项（宁缺毋滥）
> **改进 A：在统一 LLM 提示词中融合“因果逻辑三元组（Causal Graph Triples）”抽取**
> - **具体修改建议**：在阶段 21（`tone_llm_processing`）的 Prompt 模板中，除原有真伪和情感标签外，增加对包含深度逻辑分析新闻的因果元素抽取，要求 LLM 判断是否有详尽的因果分析，并输出新闻中明确列出的 `[驱动因素, 金融科技事件, 预期/实际业务结果]` 因果三元组。
> - **论文依据**：参考论文 1.2 节 Cause-effect relationship extraction 及 Table 1 的 Step 4 (Identify Causes) 和 Step 5 (Identify Outcomes) 以及 Table 8中对分析深度的市场反应结论。
> - **边际贡献**：解决纯情感分析下金融科技效应的“机制黑箱”顾虑。能精准区分“被动合规披露性质的肤浅科技声明”与“具备深层战略协同逻辑的严肃科技创新”，提供直接用于内生性检验或替代机制检验的多维异质性文本指标，显著增强项目质量。

> **改进 B：引入自适应重试与上下文补充（类RAG）解决局部事实缺失截断**
> - **具体修改建议**：在核心推演模块中，若 LLM 判断当前抽取段落缺乏足够的主体确认信息或缺乏提取因因/果的完整上下文（即论文中提及的 "I need more context"），设置重入队列回溯原始新闻更深层次（或其余部分）进行局部增强读取。
> - **论文依据**：论文 1.2 节的 Retrieval Augmented Generation (RAG) 机制设计，旨在解决长财务文档中关联主体模糊的问题。
> - **边际贡献**：彻底消除由于局部抽取或简单截断而导致大模型在长篇宏观综述类新闻中对单一银行个体的“强行幻觉推断”。

### 3. 冗余剥离
**剔除传统词典与特征覆盖率稽核机制**：论文表 IA12 和正文（第4.1与4.2节）确凿证实：基于 GPT 提取的复杂因果与情感特征能够完全吸收并替代 LM 词典法 (bag-of-words) 和基础 FinBERT 在实证层面的解释力。当前配置 `config.yaml` 中遗留的绑定执行流程（如 `22_words_tone.parquet`, `23_bert_tone.parquet`）及配套评估 ` dict_coverage_audit ` 实为低效累赘。建议直接放弃并剥离词典辅助配置及评估代码，专精使用 LLM Ensemble 进行降维抽取。

## 第二部分：项目重构与优化执行计划书

### 1. 优先级排布
- **速赢项（Quick Wins）**：通过修改配置文件关闭低效的词典覆盖率审计、词典特征抽提，并将因果结构的字段注入到阶段 21 的 `prompt_template` 与 JSON 响应格式约束中。
- **核心攻坚项**：基于大模型提取的系统化“动因(Causes)”与“后果(Effects)”数据，进行降维聚簇，在之后的变量面板聚合（阶段 40+）阶段，重构带有异质类别权重的变量矩阵（例如构建 "Innovation-driven FinTech Index"）。

### 2. 阶段化执行指令 (SOP)

**阶段一（机制重塑与数据清洗）：升级 LLM 并行抽取内核**
- **核心动作指令**：
  1. 在 `config.yaml` 模块三（tone_llm_processing）的 `<output_format>` 要求中，新增 `detailed_causal_analysis` (boolean), `fintech_causes` (array), `fintech_outcomes` (array) 字段。
  2. 在 `<step2_sentiment>` 或新增 `<step3_causal>` 提示内明令：重点发掘该银行发展各项金融科技底层的事件驱动前因与落地的实际业务后果。若无详尽缘由，必须留空数组，杜绝模型主观脑补。
- **交付物标准**：能够跑通的高质量 `21_tone_llms.parquet` 文件，非但具备准确的情感得分，必须在包含深度分析的新闻行中生成结构良好、无幻觉的 JSON 数组结构因果提取结果。

**阶段二（实证与模型重构）：非标准叙事的异质性衡量检验**
- **核心动作指令**：
  1. 在 4X 阶段面板数据合成逻辑中，将各类银行每一年度通过具有“深度因果要素标注”的新闻计算出的占比及其对应情感分数，构建出新型自变量。
  2. 运用基础自然语言处理（如聚类或关键词频）对 `[fintech_causes]` 列的驱动词（例：迎合监管 vs 抢占市场）进行二次聚类映射至两到三大主因子。
- **稳健性检验标准**：在 DID/Bartik IV 实证回归框架中，分别以“单纯正面新闻总数情绪指数”与“带有明确业务因果链的正面新闻索引”为核心自变量跑模型，检验后者的长生命周期和去噪音效果是否符合并超越学术基准。

**阶段三（结论重构）：刷新文章框架**
- **核心动作指令**：调整实证论文行文重点，实证结论必须着重凸显“金融科技信息质量（因果揭示深度）对于市场认知修正与流动性提升机制的中介作用”。剥离以往对于金融科技仅处于文本统计次数维度的探讨。

### 3. 风险预案 (Plan B)
**致命卡点预判**：要求小模型或中等算力 LLM 同时兼顾**严苛情感判定（真伪评估）**与**大段落中的因果分离任务**，极易使得 LLM 分散注意力引发主要任务（真伪鉴定准确率）崩盘或引发大规模的批量 JSON 解析失败。
- **替代方案 (Plan B)**：**流水线解耦**。
  保持现阶段 21 负责粗粒度、高准度“真伪判别”和“情感定性”不动。在流水线尾端设立一个 **异步后处理模块 (阶段 21b)**。在确认新闻为金融科技核心资产新闻 (`is_bank_fintech_news: true`) 的基础上，专门针对该缩小的长文本语料库，发起第二轮的纯因果提取调用（甚至可以升级调用具有更强上下文理解的模型），并将输出结果合流回溯至主面板。在此解耦模式下，提取能力不影响前置环节稳定性，同时大幅节省 API 推理开销。
