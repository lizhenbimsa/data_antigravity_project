# 中国上市公司数字化水平测度与演化研究——来自年报文本的经验证据_胡忠义

=========================================
## 第一部分：基于参考论文的项目分析与诊断报告

**1. 范式映射与盲区诊断：**
- **论文核心机制：** 论文指出传统的数字化技术词典（如吴非团队设定的“底层技术”与“技术实践应用”）受限于词典规模小、难以动态扩展等瓶颈，无法精准捕捉长短不一的新兴技术名词。为此，论文运用 BERT-GlobalPointer-Mask 深度学习模型进行了自动化的命名实体（术语）识别，并拓展为“数字化技术、数字化模式、数字化产业、数字化系统、数字化基础设施”五个维度的系统性测度。
- **盲区诊断：** 当前《news_process》项目在金融科技新闻的筛选（阶段12：依赖静态 `fintech_dict_file`）及大模型验证阶段（阶段21 prompt：将 `fintech_category` 框死于“底层技术”或“应用场景”）中，高度束缚于固化的静态词典及落后的二元分类法。这不仅严重漏测了银行业逐年迭代的新型金融科技相关名词概念（尤其是长组合术语），也缺乏对银行业在数字化基础设施建设及系统级平台部署等细粒度维度的区分。

**2. 实质性改进项（宁缺毋滥）：**
- **改进 A：金融科技量度五维重构体系**
  - **具体修改建议：** 将阶段21中 LLM Prompt 里的 `fintech_category` 分类体系由传统的“底层技术或应用场景”扩展为“技术、模式、产业、系统、基础设施”五类，对新闻提及的金融科技动作进行重新打标归类。 
  - **论文依据：** 胡忠义(2025) 的5.3.2章节“各维度数字化水平演化分析”，打破了吴非(2021)的粗放二元划分标准。
  - **预期的边际贡献/解决的内生性问题：** 解决传统粗粒度分类极易导致的异质性抹除偏误（Heterogeneity Erasing Bias），通过更精细的五维划分，可精准挖掘出银行数字转型路径（如大型银行偏重“基础设施”，中小银行偏重“模式与应用场景”）的截面异质性演化。

- **改进 B：引入动态术语（新词）发现与词典演化扩充机制**
  - **具体修改建议：** 突破现有严格静态关键词匹配（阶段12）拦截逻辑。引入自动化新兴术语挖掘管线（基于轻量化 NER 模型或 LLM 反问机制），按年度从当前新闻语料池中自动萃取出未能涵括的“跨界/新兴长术语”（如大模型风控中台等），并动态扩表。
  - **论文依据：** 论文第4部分对新术语(distinct)和长术语识别能力的分析及 BERT-GlobalPointer-Mask 的应用理念。
  - **预期的边际贡献/解决的内生性问题：** 缓解由于“静态词典无法随着时间序列演化追踪科技迭代”而导致的选择性时间截断偏误（Time-varying Selection Bias），保障长期纵跨样本（如从2015到2025）提取覆盖率的统计连贯性。

**3. 冗余剥离：**
- **建议剔除的伪需求：** 建议剔除/剥离 阶段12 `fintech_news_classification` 中一刀切的 `min_distinct_keywords` 刚性过滤项。对于出现极少量甚至零静态匹配词、但由高权重权威媒体发布的带有特定技术语境的新闻，直接抛弃极不合理。过度依赖静态命中数量门槛，反而剥夺了 LLM 后来进行真伪验证的能力与发现新术语的可能性。

## 第二部分：项目重构与优化执行计划书

**1. 优先级排布：**
- **速赢项（Quick Wins）**：修改 `config.yaml` 阶段21 Prompt 中 `fintech_category` 输出限制，立即过渡为五维结构（实施成本极低，预期收益极高）。
- **核心攻坚项**：开发动态金融科技新名词发现机制模块（建立增量词典自更新循环），降低因为静态词典落后带来的检索漏检。

**2. 阶段化执行指令 (SOP)：**

- **阶段一（机制重塑/数据清洗）：**
  - **核心动作指令**：
    1. 覆写 `news_process/config/config.yaml` 阶段21 `<output_format>` 内容。将 `"fintech_category"` 的输出描述改为：`"数字化技术/数字化模式/数字化产业/数字化系统/数字化基础设施（false 时填 null）"`。
    2. 同步放宽阶段12预筛阀值，对包含泛型银行前置条件的新闻不再施加机械的 `min_distinct_keywords: 3` 上限，允许疑似新技术报道进入LLM流水线。
  - **交付物**：更新适配完毕的分类体系及其 `config.yaml`。

- **阶段二（实证/模型重构与检验）：**
  - **核心动作指令**：
    1. 新建流水线脚本当作自动化发现模块 `12b_term_expansion_discovery.py`。
    2. 基于现有优质（已被人工验证为 true，但静态命中率低）的数据集，利用 LLM / CoT 提示词扮演实体提取器（Entity Extractor），批量识别属于金融科技但不属于现有 `fintech_dict.json` 的长短术语。
    3. 加入词频聚合过滤机制，生成并合并至 `fintech_dict_v2_dynamic.json` 中。
  - **稳健性检验标准**：抽样输出的50个新实体交由基于现有判卷算法进行独立对照度量（新旧词典覆盖率审计），报告 P/R 相关指标的相对提升率。

- **阶段三（结论重构）：**
  - **核心动作指令**：在最终的 `45_panel_export_main.py` 年度面板脚本中，除了计算宏观 FinTech 频率指数外，按照新划分产生的五维分类各自聚合并拆分（如：曝光量_技术, 曝光量_基础设施等）生成5个相互独立的列变量输出至 Bank-Year 平衡面板，全面支持异质性回归。

**3. 风险预案 (Plan B)：**
- **致命卡点预判**：本地流水线上缺乏标注高质量NER数据集，没有算力针对学术报告建议自建或采用 BERT-GlobalPointer-Mask 模型展开端到端微调训练，开发成本过高。
- **替代方案 (Plan B)**：妥协放弃高昂原生的深度学习NER训练成本。完全转移给现已部署并且响应及时的云端轻量级大模型（如 Gemini 3 Flash 或 Claude 4.5 Haiku），在日常跑通 `21_tone_llms.py` 时增加一个返回字段 `"novel_fintech_terms_mentioned": [新词列表]`。该并发动作既不增加新模型负担，又能在无标注数据代价下完成长尾技术名词发现与累积。
