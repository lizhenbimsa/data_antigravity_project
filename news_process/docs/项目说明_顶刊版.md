## 摘要（Executive Summary）

本项目是一套**端到端、声明式、可独立复现**的研究数据基础设施，目标是把 2007–2024 年间约 40 万条中文财经新闻文本，系统地转换为一个 1,771 家中国银行 × 18 年的银行—金融科技互动面板数据集，并支撑 **11 篇拟投顶刊与 CSSCI 的实证研究**（3 篇 SSCI 二档 + 4 篇 CSSCI + 2 篇方法学 + 2 篇 NLP）。

**核心方法学贡献**有四：

1. **三轨独立情感测度**（dictionary × LLM × BERT），并以 Cohen κ / Krippendorff α / Cronbach α / HTMT 双 cutoff 对三轨进行可验证的判别效度审计；
2. **构念—测度匹配的双轨化设计**（`_full` vs `_ctx`，Tetlock 2007 *JF* / Loughran-McDonald 2016 *JAR* 现代标准），通过预先物化 `content_ctx` 列，在 stage 21 之前即可消费上下文窗口，从而避免"全文语调对单家银行的错误归因"——这是项目相对于现有中文银行业文本研究的**第一个不可让渡的设计承诺**；
3. **8 项顶刊指标的真双轨实施**（LM 2011 *JF* 非情感四子词典 / Li 2010 *JAR* FLS 双门控 / You 2018 *FAJ* + Bonsall 2017 *JAE* 词典清晰度 / Hales 2011 *CAR* 数值强度 / Baker-Bloom-Davis 2016 *QJE* EPU 合并 / Solomon 2012 *RFS* 媒体三级权重 / BERTopic D1 + 算法 O(N²)→O(N·k) 重写的 staleness D2 + LLM CEO NER D4 / 第 10 篇 cross_outlet 分歧 + 第 11 篇外部信息环境质量）；
4. **顶刊 reproducibility 硬约束**：append-only JSONL + SHA-256 manifest 的 LLM 响应归档（v3.7.0 DC3），即使闭源模型从 GPT-5.4 升至 5.5，仍可从冻结的 prompt v8 字节级哈希 + 归档响应字节级 reproduce 主表。

**工程纪律**层面，整套流水线由 39 个 ≤ 30 行的 thin shim 调用 20 个生产 stage 与 17 个验证 stage 组成（声明于 `core/dag.py::STAGES_MAIN` 与 `STAGES_VALIDATION` 这两个单源真值），每个 stage 作为独立子进程运行，输出 198 个 `.parquet` 中间产物（累计约 9.06 GB），并由 2,031 个测试用例（1,747 fast + 284 integration）通过黄金基线列哈希进行回归保护。截至本文档撰写日，仓库已经历 369 次 commit 与 17 轮方法学 audit（v3.7.1 阶段 9 轮 audit / 211 finding / 42 修 / 5 follow-up），生产就绪自评为 9 Green / 2 Yellow / 0 Red。

**面向审稿人的承诺**：本项目的所有核心指标 (i) 有理论文献锚点（Tetlock 2007 / Loughran-McDonald 2011, 2016 / Li 2010 / You 2018 / Bonsall 2017 / Hales 2011 / Baker-Bloom-Davis 2016 / Solomon 2012 / Acharya-Anginer-Warburton 2016 等顶刊），(ii) 有字节级冻结的 prompt 与词典版本（Prompt v8，SHA-256 入 sidecar JSON），(iii) 有独立的稳健性 stage（39a/39c/39d/39e/39f），(iv) 可在 Stata IC（≤ 2,048 列）与 MP（≤ 120,000 列）双入口下复现，(v) 受标准的预承诺、披露与伦理治理约束（详见 §9–§10）。

## 一、研究动机与文献定位

### 1.1 文献空白

近二十年来，文本计量金融学（textual finance）已发展出三条主干线索：(i) **基于词典的语调/可读性测度**——Loughran-McDonald 2011 *JF* 的金融词典与其 2014–2016 *JAR* 系列扩展、Li 2008 *JAE* 与 Bonsall 2017 *JAE* 的 Fog/Bog 可读性、You & Zhang 2018 *FAJ* 的清晰度（Clarity）； (ii) **基于结构化标注与监督学习的语调与主题测度**——Tetlock 2007 *JF* 媒体悲观主义、Tetlock-Saar-Tsechinsky-Macskassy 2008 *JF* 公司语调、Hassan-Hollander-van Lent-Tahoun 2019 *QJE* 政治风险测度； (iii) **基于现代神经语言模型与生成式 AI 的语义测度**——Bybee-Kelly-Manela-Xiu 2023 *JF* / 2024 *JFE* 主题、Chen-Kelly-Xiu 2022 *RFS* 嵌入、Lopez-Lira-Tang 2024 *JF* 与 Eisfeldt-Schubert-Zhang 2024 *RFS* 的 LLM 金融文本应用。

然而，**针对中国银行业**且能同时满足以下五项条件的文本计量基础设施，迄今**没有公开可复现的实现**：

1. **样本覆盖**：覆盖全部三类商业银行（国有 / 政策性 / 股份制 / 城商 / 农商 / 民营 / 外资 / 直销 / 央行）共 1,771 家，而非常见的 16 家上市银行或 30–40 家系统重要性银行；
2. **测度多元**：同时实现 Loughran-McDonald 词典体系（含 uncertainty / litigation / constraining / modal strong 四子词典 v0.1.5）、LLM 三家厂商投票（GPT-4o + Claude 3.5 Sonnet + Gemini 1.5 Pro，三家模型 snapshot 字节级冻结）与 5 种 BERT 模型（含私有 FinBERT2）三套**独立路径**；
3. **构念—测度匹配**：在每一个核心情感构念上同时提供 `_full`（全文）与 `_ctx`（银行提及上下文窗口）双轨，以契合 Tetlock 2007 / L&M 2016 *JAR* 关于"entity-attributed sentiment"的现代标准；
4. **判别效度可审计**：以 Cohen κ（39a inter-track）、Krippendorff α（39f cross-media）、Cronbach α + HTMT 双 cutoff 0.85/0.90 + 1000-rep permutation（39c construct orthogonality、39d/39e discriminant validity）四道独立闸门系统化检验所有指标之间的判别性；
5. **LLM 时代的 reproducibility 硬约束**：以 append-only JSONL + SHA-256 manifest 持久化每一次 LLM 响应（v3.7.0 DC3），并以 Git LFS 与冻结的 prompt v8 字节哈希联合保证"即使 OpenAI 把 GPT-5.4 弃用、Anthropic 把 Claude 4 弃用，主表也可被独立重建"。

本项目是为此空白而设计的**研究基础设施**，而非单一论文。它的产出形态既是 11 篇拟投顶刊与 CSSCI 的论文（详见 §7），也是一份附 Stata replication 包（详见 §10）可被任何第三方独立运行的可复现协议。

### 1.2 学科定位

本项目同时位于三个子领域的交集：

- **银行业实证**（Banking Empirics）：Berger-Klapper-Turk-Ariss 2009 *JFI* / Acharya-Anginer-Warburton 2016 *RFS* "implicit guarantee" 框架 / Iyer-Da Rocha-Lopes-Peydró 2014 *JF* 银行—银行间风险；
- **媒体—金融互动**（Media-Finance Interaction）：Tetlock 2007 *JF* / Engelberg-Parsons 2011 *JF* / Solomon 2012 *RFS* / Niessner 2015 *JFE* / Drake-Guest-Twedt 2014 *RFS*；
- **文本计量金融学**（Textual Finance）：L&M 2011, 2016 / Li 2010 *JAR* FLS / Bybee 2023 *JF* / Chen-Kelly-Xiu 2022 *RFS* / Hassan 2019 *QJE*。

我们用 **"Bank-FinTech 媒体—监管—市场三角"** 一句话给项目定位：在中国金融科技（FinTech）从 2013 年 6 月 13 日"余额宝上线"事件至 2020 年 11 月 3 日"蚂蚁 IPO 暂停"事件期间，**媒体如何介入银行—金融科技互动**、**这种介入是否构成对银行行为（风险承担、信贷扩张、战略差异化）的独立信息冲击**、**以及在此信息冲击下中国银行业风险结构如何重组**。这与 2018 *JF* 银行业专刊以来的 "shadow banking × fintech × media" 三主题完全契合，且能直接对接 2024–2025 年 *JF*/*JFE*/*RFS* 在 LLM-based textual finance 主题上的活跃方向。

### 1.3 为什么"现在"是合适的时间窗

三个外部条件首次同时具备：(i) 中国财经媒体语料的去重—合并—银行命名实体可识别的完备性，在 2024 年下半年随 NFRA 公开商业银行总名录与 jieba == 0.42.1 中文分词稳定性已经达到；(ii) LLM 价格在 2025 年初降至可批量调用的水平（OpenAI GPT-4o / Claude 3.5 Sonnet / Gemini 1.5 Pro 三家月成本均在 USD 100 量级内可完成一次全样本扫描）；(iii) Stata 19 / pyreadstat 0.2.x / pandas 2.x 等基础工具已经稳定到可以承载 2,033 列、9 GB 的 panel 数据集。

### 2.4 样本边界与潜在偏差

我们在 §2.4 主动**预先披露**三项可能引起审稿人质疑的样本边界问题：

1. **媒体覆盖偏差**：tier 1 农商行（1,563 家）中约 80% 在 60+ 媒体源中样本期内 0 次被提及；这是真实的覆盖偏差而非数据错误。处理协议：(i) 主回归保留全样本以反映"未被报道"本身的信息含量，(ii) 设置 `coverage_indicator` dummy 控制，(iii) 提供 N ≥ 5 提及子样本作为 robustness。
2. **媒体源时间不均匀**：60+ 媒体中部分仅在 2014 年之后才进入语料库（数字化进度差异）。处理协议：所有 stage 38a `temporal_mask_test` 通过年份子样本回归验证主效应稳定性。
3. **金融科技概念的时间漂移**：2013–2018 年的 "FinTech" 与 2019 年之后存在概念外延扩展。处理协议：fintech_dict 按年份分层维护（v3.5.x 加入 sub-period dictionary patch），并以 stage 32a `dedup_threshold_sensitivity` 系统检验。

## 三、系统架构：声明式 DAG 与 thin shim 契约

### 3.1 设计哲学

整个流水线遵循三条不可让渡的工程纪律：

1. **声明式 DAG（Declarative DAG）单源真值**：`core/dag.py::STAGES_MAIN`（19 stage）与 `STAGES_VALIDATION`（18 stage）是"哪些阶段存在 / 何时运行"的**唯一权威**。主 orchestrator `run_pipeline_function.py` 与 `run_pipeline_validation.py` 都从此处 `import`，并由 `tests/integration/test_dag_consistency.py` 通过 `is` 身份比对验证两端绑定一致；
2. **Thin shim 调用契约**：仓库根的 40 个 `NN_*.py` 入口（含字母变体 27c / 30a / 32a / 38a / 38b / 39a / 39c / 39d / 39e / 39f / 39g 共 11 个）每个 ≤ 30 行，仅负责"import 业务函数 + main() 调用"。**所有业务逻辑只能位于 `news_process/pipeline/*` 与 `news_process/validation/*`**。这条规则由 pre-commit hook 与 `pytest tests/integration/test_dag_consistency.py` 联合执行；
3. **Subprocess 隔离**：每个 stage 由 orchestrator 启动为独立 Python 子进程；任一 stage 崩溃不会污染其他 stage 的内存或模型加载状态，便于断点续跑。

> **审稿人价值**：当审稿人问"如果你只想重跑 stage 21（LLM 投票），需要不需要重跑 stage 11/12？"时，我们的回答可被字节级证明——`python 21_tone_llms.py` 即可独立运行；`data/processed/21_tone_llms.parquet` 之前的 11 个 stage 全部读自磁盘缓存，不依赖任何 in-memory 状态。

### 3.2 单源真值（Single Sources of Truth）

四个权威源——**任何变更都必须同步更新**：

| 权威源 | 位置 | 范围 |
| --- | --- | --- |
| Stage 注册 | `core/dag.py::STAGES_MAIN` / `STAGES_VALIDATION` | DAG 拓扑 |

## 五、文本智能层：三轨情感分析的方法学辩护

### 5.1 为什么是"三轨"，而不是"单轨"

任何单一情感测度路径都存在结构性盲点：

- **词典法（L&M 2011）**：透明、零成本、可复现；但严重低估上下文与否定（"不下降"被读成"下降"）；
- **LLM 法**：语义理解最强；但对 prompt 敏感、对 sampling temperature 敏感、且闭源模型 deprecation 风险高；
- **BERT 法（FinBERT2 + 4 个开源）**：在词典与 LLM 之间提供中间值；但需要 GPU 与私有模型，对独立复现者不友好。

我们的设计原则：**主回归用 LLM，但每张主表都附词典版与 BERT 版作 robustness**。如果三轨在主回归里方向一致且显著性接近，故事才站得住；如果不一致，我们在论文中明确报告分歧并讨论其方法学含义（这正是第 10 篇 `bank_media_disagreement` 的研究问题来源）。

我们对 LLM 时代的 reproducibility 危机持谨慎悲观态度：闭源模型 deprecation 是常态而非例外。因此 v3.7.0 引入 **DC3 LLM archive 模块**作为顶刊 reproducibility 硬约束：

## 六、双轨化设计：构念—测度匹配的精确化

### 6.1 问题陈述

设某文章 $A$ 提及银行 $B_1$ 与 $B_2$，但在 1,000 字篇幅中只用 ±50 字窗口讨论 $B_1$。传统 firm-level sentiment 测度 $s(A, B_1) = \mathrm{tone}(A)$ 会把 $B_2$ 相关上下文也归因到 $B_1$ 上——这是 Tetlock 2007 *JF* 与 L&M 2016 *JAR* 在 modern textual finance literature 中明确警告的 "entity attribution failure"。

### 6.2 解决方案

在 stage 13 `materialize_ctx` 之前预先物化两份内容：

- **`content_full`**：全文（去 HTML、规范编码后）；
- **`content_ctx`**：以 banking entity 提及点为锚，前后各取 N tokens 切窗（默认 ±50 tokens，可配置）。

下游所有情感与文本特征 stage（14 / 15 / 17 / 18 / 21 / 22 / 23 / 24）都**独立扫描** `content_full` 与 `content_ctx`，输出 `*_full` 与 `*_ctx` 两列。聚合到 panel 时也同步生成 `mean_*_{full,ctx}` 两列。

### 6.3 双轨化覆盖矩阵

| 指标 | `_full` | `_ctx` | Main treatment（v3.6.0+）|
| --- | :-: | :-: | --- |
| `llm_vote_tone` | ✅ | ✅ | `_ctx` （P1 Plan E G3 切换） |
| `fintech_intensity_score` | ✅ | ✅ | `_ctx` |
| `policy_cosine_sim` | ✅ | ✅ | `_ctx` |
| `mean_clarity_score` | ✅ | ✅ | `_full` 与 `_ctx` 并列报告 |
| `mean_frac_definite` | ✅ | ✅ | 并列 |
| `frac_amb_articles` | ✅ | ✅ | 并列 |
| `mean_num_intensity` | ✅ | ✅ | 并列 |
| `herd_weight` | ✅ | ✅ | 并列（v3.6.0 BREAKING：废 v3.5.x 单列） |
| BERT tone（5 模型） | ✅ | ✅ | robustness only |
| LM tone | ✅ | ✅ | robustness only |

### 8.2 D-day 校准与人工标注

### 8.3 判别效度的双 cutoff 协议

`39d_lexical_discriminant_validity` 与 `39e_lm_discriminant_validity` 采用以下协议（v3.5.1 锁定）：

- **HTMT 双 cutoff**：0.85（liberal）+ 0.90（conservative），两个 cutoff 都需要被跨 3 个核心 indicator 满足；
- **Cohen κ**：三轨 pairwise，> 0.40 substantial agreement；
- **Cronbach α**：indicator family 内 > 0.70；
- **1000-rep permutation**：seed=42，置换零分布作为非参数显著性参照；
- **on-disk pairwise**：< 1 GB（避免内存爆炸）；
- **ctx-fallback mask**：当 `_ctx` 列因银行未在文章中提及而 NaN 时，下游 mask 而非补零。

### 8.4 媒体多元化与三级 tier

## 十一、审稿人 FAQ（预期质询与项目回应）

> 以下 12 题选自项目内部预演的 25 题 FAQ。完整版见综合白皮书第十九章。

**Q1：你们如何保证 LLM 投票不是在乱编？**

A：三层防御。(i) **三轨独立**——LLM、词典、BERT 同时跑，主表必附词典版与 BERT 版作 robustness；(ii) **判别效度审计**——`39a_inter_track_kappa` 报告 Cohen κ（要求 > 0.40）、`39c_construct_orthogonality` 报告 HTMT 双 cutoff（0.85/0.90 均需满足）；(iii) **D-day 校准**——`32_news_llms_human` 模块对一定比例样本进行人工标注比对（当前 calibration plan v5.1 待重启 Day 0）。

**Q2：Prompt 变了怎么办？**

A：Prompt v8 已字节级冻结，SHA-256 写入 `data/processed/v3_5_1_constants.json` sidecar。任何后续 prompt 变更会更新版本号（v9 / v10 …），并保留旧版本响应归档作为 robustness。`39_prompt_sensitivity` stage 系统化测试 prompt 字节级敏感性。

**Q3：模型 deprecation 怎么办？**

A：v3.7.0 DC3 LLM archive 模块以 append-only JSONL + SHA-256 manifest 持久化所有 LLM 响应（~5 GB 预估，Git LFS）。即使 GPT-5.4 → 5.5 升级或 Gemini 1.5 弃用，主表可从冻结的 prompt + 归档响应字节级复现。

**Q4：1,771 家银行里 1,500+ 家几乎没有媒体覆盖，怎么处理？**

A：见 §2.4。主回归保留全样本以反映"未被报道"本身的信息含量，并设 `coverage_indicator` dummy 控制；N ≥ 5 提及子样本作 robustness。

**Q5：`_full` 与 `_ctx` 双轨在主表里到底用哪个？**

A：由每篇 paper 的 `paper_spec.yaml::treatment::primary` 决定。v3.6.0 起，P1 `bank_fintech_tone` 切到 `_ctx`（Tetlock 2007 *JF* / L&M 2016 *JAR* 现代标准要求 entity-attributed sentiment 作 main）；其余 paper 见各自 spec。两轨方向冲突的 paper 单独立项（第 11 篇）。

**Q6：你们的银行命名实体匹配怎么避免误匹配？**

A：`config/bank_keywords.json` + Aho-Corasick 多模式匹配 + `bank_name_exclusions.json` 排除集 + `pipeline/text/canonicalization.py` 同名异指消歧。`36_entity_masking_test` 通过对抗性遮蔽测试系统化检验匹配稳健性。

**Q7：媒体多元化与等权问题？**

A：v3.6.1 落地 Solomon 2012 *RFS* 三级 tier 权重（_tier 列 append-only），并在 `compute_media_tier_weights` 中真接入。

**Q8：双轨切换 ATT 漂移是否被监控？**

A：`scripts/audit/att_drift_simulation.py` user-run gate 监控；结果纳入每篇 paper 的 robustness appendix。

**Q9：金融科技概念时间漂移？**

A：fintech_dict 按年份分层维护（v3.5.x sub-period patch），并以 `32a_dedup_threshold_sensitivity` 检验。

**Q10：你们的 .dta 文件版本与 Stata 版本是否一致？**

A：pyreadstat 写出 `.dta` format version 118（spec 编号），Stata 19 读取无任何限制（变量名 32 字符 / value label 32K bytes 等均满足）。`.dta` spec 与 Stata 应用程序版本是两个独立概念，不要混淆。

**Q11：如果只能复现你们的一张主表，需要哪些资产？**

A：(i) 仓库 + `pyproject.toml` + `requirements.lock`；(ii) `data/raw/*.xlsx`（受数据授权约束，可申请共享）；(iii) `data/llm_archive/responses/*.jsonl`（Git LFS）；(iv) `config/v2_3_implementation_constants.json` + `data/processed/v3_5_1_constants.json` sidecar；(v) `bank_list.yaml`（NFRA 派生）。`papers/_common/stata_runner.py doctor` 会逐项验证。

**Q12：项目对 11 篇接收的 KPI 是否过于乐观？**

A：KPI 11 不是接收承诺，而是 portfolio 目标。Plan E §3 治理解锁后主线 7 篇可立投；加上第 10 / 11 篇与衍生 2 篇，构成 11 paper 矩阵。EV（expected value）修正后 ≈ 3–5 paper 接收为治理重审基线。我们对此持谨慎乐观态度，详见 MEMORY `paper_portfolio_decision_gates`（43–73 次用户授权 gate / 3–5 年）。

## 结语

本项目把"看似软的文本指标"做成了"可被顶刊审稿人独立核查的硬指标"。在 LLM 时代，**Reproducibility 的边界已经从"代码+数据"扩展到"代码+数据+模型响应字节"**——我们对此采取了主动的工程承诺（DC3 archive）与方法学承诺（双轨化 + 判别效度 + Prompt 字节冻结）。

我们不为某一篇具体论文写说明书；我们为一套**可复现的研究基础设施**写说明书。在这套基础设施之上的 11 篇论文，是这套基础设施成熟度的测试用例，而不是它存在的理由。
